Typography

Source Serif 4 (serif) for H1/H2 page titles and section headers — adds institutional authority. Inter (sans) for H3 through body. JetBrains Mono for telemetry data, device IDs, timestamps.

CE influence: Serif at heading level only preserves data-density readability below H2. Body line height is 1.7 (vs MT standard 1.6) for more generous vertical rhythm.

Controlled Autonomy Messaging

Visible throughout the UI wherever agents act:

  • 1. Autonomy level indicator on every agent card (dot visualization, 0-4)
  • 2. Approval queue as a primary nav item — not hidden in settings
  • 3. Constraint visibility — on agent detail pages, constraints listed prominently, not collapsed
  • 4. "Why did the agent do this?" link on every action, expanding reasoning chain

Printable Status Reports

Monthly/weekly fleet status report, exportable as PDF. Uses navy (#1E3A5F) as header color in light-panel print context. Serif section titles with navy underline.

Print styles switch to white background, navy headers, and serif section titles. See @media print block in source CSS.

Mixing Notes

Minimal Tech 80% + Corporate Enterprise 20%. The CE influence is surgical: five specific modifications that shift trust perception without tipping into legacy enterprise territory.

The 5 Corporate Enterprise Elements

#ElementMT DefaultCE ModificationRationale
1 Serif headings Sans-serif throughout Source Serif 4 at H1/H2 Adds institutional gravitas. "This is a platform, not a toy." Serif at heading level only preserves data-density readability below H2.
2 Button radius + shadow 6px radius, no shadow 4px radius, box-shadow More conservative geometry signals reliability. Subtle shadow adds physical weight — buttons feel like controls, not decoration.
3 Table header treatment Transparent, 1px border #141420 fill, 2px border Tables become formal reports. Enterprise buyers print and screenshot dashboards for steering committees. Scannable header rows matter.
4 Trust badges + compliance Absent SOC 2/ISO badges, audit trail, approval queue Directly addresses "How do I know this is safe?" The audit trail is not a log viewer — it's a trust artifact.
5 Transition timing 150ms 200ms More deliberate pacing. The UI moves with intention, not urgency. A platform governing 50K devices should feel steady.

What Was Considered and Rejected

ConsideredReason for Rejection
Light modeConflicts with primary use case. IoTGo is watched in NOCs, control rooms, and operations centers. Dark mode is the operational standard (Datadog, Grafana, PagerDuty all default dark).
Navy primaryWould make IoTGo indistinguishable from every enterprise dashboard (Salesforce, ServiceNow, Jira). Teal maintains the "modern infrastructure" signal while navy serves as secondary structural accent.
Mega menuIoTGo's information architecture is too flat — 7 top-level sections, minimal nesting. Mega menu solves a problem that doesn't exist here.
Serif body textReadability collapses at data-dense sizes. Body text at 16px in serif competes with mono telemetry data and small-caption labels.
Gold accentGold signals finance, premium tiers, or rewards. Wrong connotation for operations software managing critical infrastructure.
Animation-heavy onboardingEnterprise buyers evaluate with procurement teams in the room. Lottie animations feel frivolous in a vendor assessment context.

Reference Energy

Datadog's density + Cloudflare's surface treatment + PagerDuty's incident patterns + institutional gravitas from serif headings and formal table styling. The result should feel like a monitoring tool built by people who've been through a SOC 2 audit.

Implementation Checklist

Phase 1: Foundation
  • Set up CSS custom properties (copy :root block)
  • Import fonts: Source Serif 4 (700), Inter (400, 500, 600), JetBrains Mono (400, 500)
  • Implement base reset and body styles
  • Build spacing utility classes from token scale
  • Define color utility classes for device health states
  • Set up 12-column grid with 1440px max-width
Phase 2: Typography
  • Implement heading styles (H1/H2 serif, H3/H4 sans)
  • Implement body, small, caption, data, and overline text styles
  • Verify line-height rendering at each scale level
  • Test serif/sans pairing at different viewport widths
Phase 3: Core Components
  • Buttons: primary (shadow), secondary, ghost, danger (all sizes)
  • Form inputs: text, select, textarea with always-visible labels
  • Cards: standard, with header/footer separators, interactive
  • Tables: header fill, status cells, mono data cells
  • Badges: all 6 status variants (health + info)
  • Autonomy level dot indicator (0-4)
Phase 4: Navigation + Layout
  • Sidebar: logo, nav items, active states, compliance footer
  • Trust bar: health score, last sync, agent status, account tier
  • Content area: proper offset for fixed 260px sidebar
  • Responsive: tablet collapse (sidebar overlay at 1024px)
Phase 5: Interaction + Feedback
  • Toast notification system (4 variants, formal language)
  • Confirmation dialog (standard + agent action variant)
  • Skeleton screens with progress text
  • Tooltip component (150ms fade, 500ms delay)
  • All hover/focus/active states per interaction table
Phase 6: Trust Elements (CE Contribution)
  • Compliance badge panel in sidebar footer
  • Agent audit trail component (timeline format)
  • Approval queue as primary navigation item
  • Constraint visibility panel on agent detail pages
  • "Why did the agent do this?" expansion on action items
  • Printable status report styles (@media print)
Phase 7: Validation
  • Side-by-side comparison with Direction A
  • Enterprise buyer gut-check: trustworthy without feeling legacy?
  • Data density test: populate with realistic fleet data (5K+ devices)
  • Accessibility: contrast ratios meet WCAG AA on all text/bg combos
  • Performance: font loading strategy (preconnect + display=swap)
  • All animations respect prefers-reduced-motion
  • Touch targets ≥ 44px on mobile
  • Dark mode only
