Direction A: Clean Room

Clinical precision for LLM threat intelligence.

Font: Inter + JetBrains Mono Accent: Emerald #10B981 Radius: 6px Mode: Light Style: Minimal Tech 80% + Bold Expressive 20%
A senior security engineer opens the JailbreakingSite catalog on Monday morning. Light floods the interface — clean white surfaces, organized taxonomy, severity indicators visible at a glance. She's scanning for new techniques that might affect her company's GPT-4 deployment. The clean room aesthetic signals rigor: every technique classified, every mitigation verified, every severity score defensible.

Skeleton Loading

Data Visualization Notes

Severity Distribution Chart: Donut or stacked bar. Segments use the full severity palette: critical (red), high (amber), medium (blue), low (gray), pass (green). No other chart colors. Minimal axis labels, Caption size (12px mono).
Coverage Heatmap: Technique taxonomy as a 2D grid — rows are categories, columns are affected models. Cell color = highest severity confirmed. 12px minimum cell, 2px gap. Tooltip on hover shows technique ID (mono) and severity.
Scan Timeline: Pass/fail dots over time for a given model target. 8px dots, color = severity of finding. No fills, no gradients. X-axis in JetBrains Mono timestamps.

Implementation Checklist

Typography & Fonts
  • Inter loaded via Google Fonts: weights 400, 500, 600 only
  • JetBrains Mono loaded via Google Fonts: weight 400 only
  • All technique IDs, scan hashes, detection signatures in JetBrains Mono
  • All severity badge labels in JetBrains Mono, uppercase, letter-spacing 0.03em
  • All technical data values (timestamps, model names in code context) in JetBrains Mono
Color & Severity
  • Severity color system (critical/high/medium/low/pass) is the primary visual interest
  • Accent green (#10B981) reserved for CTAs, active nav, focus rings, and PASS severity only
  • Muted severity variants for row highlights and badge backgrounds — never full-opacity fills on large surfaces
  • WCAG AA contrast: text-primary #171717 on bg-primary #FAFAFA (16.8:1 ✓)
  • WCAG AA contrast: accent #10B981 on bg-surface #FFFFFF (4.5:1 ✓)
  • Severity badge text always meets 4.5:1 on its muted background
  • No gradients anywhere
  • Light mode only — no dark mode toggle
Layout
  • Sidebar: 240px fixed, collapsible to icon rail (64px), taxonomy navigation only
  • Main: scrollable catalog with sticky filter/search bar at top
  • Technique detail panel: slide-in from right, 480px wide, overlay on mobile
  • Max-width 1200px on wide viewports
  • 12-column grid, 24px gutter
Components
  • All buttons: 6px radius, no box-shadows
  • All inputs: 6px radius, 1px border, green focus ring (3px glow)
  • All cards: 8px radius, 1px border-default, no background color on card itself
  • Technique cards: 3px left border in severity color, no other decoration
  • Severity badges: pill-shaped (radius 999px), monospace, uppercase, 200ms load animation
  • Scan result rows: hover background = severity-muted of row's severity level
  • Scan progress bar: animated fill, 4px height, rounded
  • No border-radius greater than 999px (pills) or 8px (cards)
Accessibility
  • Severity communicated through label text AND color — never color alone
  • Focus states visible on all interactive elements (2px green outline)
  • Touch targets ≥ 44px on mobile
  • Scan result table uses role="table" / role="row" semantics
  • All icons have aria-label or are aria-hidden with adjacent text
  • All animations respect prefers-reduced-motion
Interaction
  • 150ms micro-interactions, 200ms max for panels and toasts
  • Skeleton loading — no spinners
  • Toast notifications: bottom-right, 4-variant system (success/error/warning/info)
  • Filter changes cross-fade catalog contents at 150ms
  • / key opens search, ⌘K opens command palette
Do Not
  • No decorative illustrations or stock imagery
  • No multiple accent colors — green only (severity palette is separate)
  • No border-radius greater than 8px on containers (pills are exempt)
  • No gradients
  • No spinners — skeleton loading only
  • No dark mode
  • No sans-serif for technique IDs, hashes, or any technical data field
