# Ryan O'Brien — The Community Contributor

| Field | Value |

## Bio

Ryan got his start contributing to a well-known Rust crate in college and caught the open-source bug. He's now a regular contributor to three active Python projects and maintains two small libraries of his own. He makes his living freelancing but invests significant side time in open-source — partly for the reputation, partly because he genuinely enjoys the craft, and partly because he's watching the rise of community marketplaces like VS Code extensions and Obsidian plugins and wants to be positioned when the next one breaks out. He plays text RPGs and is excited about composable game systems as a design space.

## Goals

1. Build and publish reusable NoizuRPG components (combat systems, magic systems) to the marketplace
2. Earn recognition as a core community contributor; gain committer status
3. Generate supplemental income from marketplace downloads or sponsorship

## Frustrations

1. Community marketplaces often have poor discoverability — well-built components get buried under low-quality entries
2. Contribution guidelines and component APIs are inconsistently documented, making it hard to know what "good" looks like
3. Revenue splits and licensing terms for marketplace contributions are often unclear until after significant investment

## Behaviors

- Scans GitHub trending daily; jumps on new frameworks early when the community is still forming
- Writes clean, well-tested Python with type hints; treats README quality as a first-class concern
- Engages in Discord and GitHub Discussions before opening PRs; builds relationships before code
- Tracks his open-source portfolio as a career asset; links contributions from his personal site

## Job to Be Done

> "When I find a growing open-source framework with a marketplace, I want clear contribution standards and fair revenue terms, so I can build high-quality components that earn recognition and income."

## Relationship to Product

Discovers NoizuRPG through GitHub trending or a Hacker News launch post. Engages immediately with the community Discord and GitHub Discussions to understand the roadmap and where contributions are welcome. Adopts the framework as his primary RPG component platform if: the API is well-designed for extension, the marketplace terms are clear, and core maintainers are responsive. Champions by writing tutorials, demo repos, and conference lightning talks. Churns if maintainers are unresponsive to PRs or the marketplace launch stalls indefinitely.

## Scenarios

1. **First Component** — Builds a modular D&D-style combat system as a NoizuRPG plugin; publishes to the marketplace with full documentation and a demo game; becomes one of the top-downloaded community components.
2. **Committer Path** — After three accepted PRs, is invited to join the maintainer team; takes ownership of the Quest Engine module and drives its v2 API design.
