# US-121: NPC Adaptive Teaching

**Persona:** Carol — Parent of blind child (42, sighted, safety/onboarding)
**Priority:** P1
**Epic:** LLM & AI Systems

## Story
As Carol, I want the tutorial NPC to recognize when my child is struggling and slow down, explain differently, or offer more help — and when they're breezing through, to stop explaining things they clearly already know — so that onboarding feels personalized rather than one-size-fits-all.

## Acceptance Criteria
- [ ] Tutorial NPCs track demonstrated competencies per player: each tutorial skill (navigation, combat, inventory, dialogue) is marked as `:not_demonstrated`, `:struggling`, `:demonstrated`, `:proficient` based on observed command success rates
- [ ] AI teaching system adapts explanation depth to competency state: `:not_demonstrated` → full explanation with step-by-step; `:struggling` → alternative explanation approach with different framing; `:demonstrated` → brief confirmation; `:proficient` → skip or offer advanced content
- [ ] Struggle detection defined as: 3+ failed attempts at the same action type within 5 minutes, or 2+ minutes of inactivity immediately after an instruction — triggers automatic NPC check-in ("Are you having trouble with that? Let me try explaining it another way.")
- [ ] Quick learner detection: completing a skill demonstration correctly on first attempt and advancing to the next without prompting → NPC acknowledges competence and offers to skip ahead ("You clearly know your way around a blade already — shall we skip the basics?")
- [ ] Tutorial NPC dialogue generated by AI using competency state as a primary prompt parameter: tone shifts from encouraging and patient (struggling) to collegial and brisk (proficient)
- [ ] All tutorial NPC interactions are screen-reader-first: step-by-step instructions delivered as numbered ARIA lists, command examples in `<code>` elements with screen-reader-friendly labels, no spatial instructions ("click the button on the left")
- [ ] Tutorial progress persists across sessions: player who logs out mid-tutorial resumes from exact competency state with NPC acknowledging the return ("Welcome back — you were learning how to equip items when we last spoke.")
- [ ] Parent account dashboard (US for parental controls) shows tutorial progress for child accounts: which skills demonstrated, where struggles occurred, time spent per section — expressed in plain language

## Notes
Competency tracking implemented as `BladeOfEternity.Tutorial.CompetencyTracker` — GenServer per tutorial player. Maintains `competency_map :: %{skill_atom => competency_level}`. Persisted to `tutorial_progress` PostgreSQL table on every state change (upsert on `{player_id, skill}`).

Skill observation: `CompetencyTracker` subscribes to game command events via PubSub. Relevant event types per skill:
- Navigation: `{:move_command, :success | :failed}`, `{:look_command, :success}`
- Combat: `{:attack_command, :success | :miss}`, `{:use_skill, :success | :failed}`
- Inventory: `{:equip_command, :success | :failed}`, `{:pickup, :success}`
- Dialogue: `{:talk_command, :success}`, `{:say_command, :sent}`

Success/failure rates tracked per skill as a sliding window (last 10 relevant events). Competency level assigned: >80% success → `:proficient`; 60–80% first attempt → `:demonstrated`; 40–60% with retry → `:struggling`; <40% or no attempts → `:not_demonstrated`.

Struggle check-in: `CompetencyTracker` uses `Process.send_after/3` to schedule inactivity checks after each instruction is delivered. If no relevant command received within 2 minutes: fires `{:check_in_needed, player_id, skill}` event. Tutorial NPC process handles event by generating an empathetic check-in via AI.

Alternative explanations: when re-explaining a struggling skill, the tutorial NPC AI prompt includes: "The player has struggled with [skill]. Previous explanation framing was [last_framing]. Use a different framing — try an analogy, a simpler step breakdown, or a different sensory metaphor." Framing type logged per attempt to avoid repeating the same approach.

Quick-learner skip offer: if all tutorial skills reach `:proficient` before tutorial completion, tutorial NPC generates an offer to skip to the main game with a brief summary of what advanced content will cover. Player accepts via YES command. Skip offer also available on first `:proficient` demonstration of each skill as a "fast track" option for that section.

Screen-reader instruction format: tutorial NPC instructions rendered as structured Phoenix templates, not raw AI text. Step-by-step instructions use an EEx template producing `<ol aria-label="Tutorial steps">` with `<li>` per step. Command examples: `<code aria-label="Command: NORTH">NORTH</code>`. AI generates only the explanation prose content; structure is template-controlled.

Parent dashboard data: `tutorial_progress` table queried by parent for child accounts — returns skill competency levels and timestamps. Displayed in plain language: "Your child has learned: moving between rooms, talking to characters. Still practicing: fighting enemies (tried 4 times, getting better)."
