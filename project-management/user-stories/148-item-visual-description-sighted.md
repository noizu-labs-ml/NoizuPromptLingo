# US-148: Item Visual Descriptions for Sighted and Low-Vision Players

**Persona:** Sarah — Low-vision explorer (34, retinitis pigmentosa)
**Priority:** P1
**Epic:** Item Framework & Equipment

## Story
As Sarah, I want items to have rich visual descriptions that I can access through the examine command so that the aesthetic dimension of gear is available to me — adding to the experience rather than being a hidden layer I'm excluded from.

## Acceptance Criteria
- [ ] Every item template includes a `visual_description` field: a 1–3 sentence prose description of color, form, texture, luminosity, and distinctive visual marks — authored or LLM-generated from material and item type
- [ ] Visual descriptions are additive: the game is fully playable without them; they appear only in the extended `examine [item]` output, not in combat narration or inventory lists
- [ ] `examine [item]` output structure: (1) item name and rarity, (2) mechanical description (stats, effects), (3) visual description, (4) lore text if identified — screen reader users navigate sections by heading
- [ ] Low-vision accommodations: high-contrast item rarity indicators in the web UI (color alone is never the only rarity signal — rarity tier name always present in text)
- [ ] Visual descriptions for enchanted items include visual effects of the enchantment: "the blade shimmers with a faint orange heat-haze" for fire enchantment; "frost patterns crystallize and evaporate on the flat of the axe" for ice enchantment
- [ ] For legendary items, the visual description is more elaborate (4–6 sentences) and references the item's history: "Thornbane's blade has darkened over centuries to a deep charcoal grey — scholars believe the discoloration comes from the blood of the Shadow Drake it slew in the Third Age."
- [ ] Visual descriptions generated by LLM are cached per item template (not per instance) — all iron longswords share the same base visual description; enchantments and quality modifiers are appended per-instance
- [ ] Sarah can configure her client to include visual descriptions in the default examine output or to require an explicit `examine visual [item]` — user preference stored server-side

## Notes
The additive principle (AC-2) is the central accessibility commitment of this feature: visual descriptions are a bonus layer, not a requirement. A player using NVDA who does not want to hear visual descriptions can skip the section with arrow navigation and lose nothing mechanical. Sarah, who has partial vision and enjoys visual detail, can access it explicitly.

Retinitis pigmentosa often preserves some central vision, meaning Sarah may be able to perceive high-contrast color differences but not fine detail. The high-contrast rarity indicators (AC-4) should use combinations that work with common color vision deficiencies: not red/green alone, but shapes or patterns alongside color.

Enchantment visual effects (AC-5) are a collaboration between the item system and the LLM: the enchantment type is passed as context, and the LLM selects visually appropriate language. Fire enchantments on different materials should read differently: a fire-enchanted iron sword looks different from a fire-enchanted crystal dagger.

The user preference for visual description inclusion (AC-8) should default to included (opt-out) for sighted/low-vision users and excluded (opt-in) for users who have indicated screen-reader-primary mode during onboarding. This preference is part of the accessibility profile established in the onboarding flow.

LLM caching per template (AC-7) is an important cost control: generating a unique visual description for every item instance would be prohibitively expensive. The template-level cache with per-instance enchantment/quality suffixes is the correct architecture.
