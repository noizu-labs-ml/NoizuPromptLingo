# US-109: Multi-Turn NPC Dialogue

**Persona:** Elena — Blind teenager (16, VoiceOver+iOS, social play)
**Priority:** P0
**Epic:** LLM & AI Systems

## Story
As Elena, I want to have real back-and-forth conversations with NPCs that flow naturally — where I can ask follow-up questions, change topics, and feel like I'm actually talking to someone — with every exchange readable via VoiceOver without hunting through cluttered text.

## Acceptance Criteria
- [ ] NPC dialogue supports extended multi-turn exchanges: player inputs and NPC responses alternate indefinitely within a conversation session, with AI maintaining full conversation thread context
- [ ] Conversation thread stored server-side per active dialogue session as ordered list of `{speaker, text, timestamp}` tuples; client never responsible for context state
- [ ] AI maintains topic tracking: current topic, topics discussed this session, topic transitions (natural vs. abrupt) — topic switches handled gracefully ("You shift the conversation to...") rather than causing context confusion
- [ ] Conversation history delivered to the screen reader as a dedicated dialogue ARIA region with `role="log"` and `aria-live="polite"`, separate from the main narrative region; new NPC responses announced without displacing prior turns
- [ ] Players can navigate dialogue history using standard ARIA log navigation (cursor keys within the log region); each entry labeled with speaker name for VoiceOver announcement ("Mirella says: ...")
- [ ] Topic exhaustion handled gracefully: when the AI determines the NPC has nothing more to say on a topic, a natural conversation close is generated ("I think I've told you all I know of that matter...") with optional redirect to another topic the NPC can discuss
- [ ] Conversation sessions have a configurable idle timeout (default 3 minutes); expired sessions emit a farewell message and return player to standard command mode
- [ ] Dialogue input mode clearly signaled to screen reader: on TALK NPC command, a status announcement "Conversation started with [NPC name]. Type your words or SAY GOODBYE to leave." is injected before the NPC's opening line

## Notes
Conversation session implemented as `BladeOfEternity.NPC.DialogueSession` — a GenServer per active conversation, supervised under the player's session supervisor. Holds: `conversation_history` (list of tuples), `topic_graph` (current topic, visited topics), `npc_state` (snapshot of NPC emotional state at conversation start, refreshed each turn from US-104), `player_id`, `npc_id`, `started_at`, `last_activity`.

Session reuse: if player re-initiates TALK with the same NPC within 10 minutes of session expiry, conversation context is rehydrated from PostgreSQL log rather than starting fresh — NPC references the recent exchange: "Back so soon? As I was saying..."

Topic tracking implemented by including a structured JSON block in the LLM response: `{"topic": "current_topic_slug", "topics_covered": [...], "suggested_redirects": [...]}`. Parsed from response, stripped before ARIA delivery. Topic slugs compared against NPC knowledge graph (US-117) to validate NPC can discuss suggested redirects.

Conversation history injected into dialogue prompt using a sliding window: last 10 turns in full, older turns as a summarized block (generated by summarization pipeline from US-103). This keeps conversation context within token budget (US-101) even for very long exchanges.

ARIA dialogue region structure in React frontend:
```html
<div role="log" aria-label="Conversation with Mirella" aria-live="polite">
  <p><strong>Mirella says:</strong> What brings you back to my stall, wanderer?</p>
  <p><strong>You say:</strong> I'm looking for passage north.</p>
  <p><strong>Mirella says:</strong> North? Through the Ashwood in this season...</p>
</div>
```

Idle timeout implemented via `Process.send_after/3` reset on each player input. On timeout: session generates farewell, publishes to player channel, GenServer terminates cleanly. PostgreSQL logs full conversation for memory processing (US-103).

VoiceOver iOS testing required: VoiceOver on iOS handles `role="log"` differently from desktop screen readers — test with actual iOS device verifying announcement behavior on new NPC turns without interrupting player's current VoiceOver focus position.
