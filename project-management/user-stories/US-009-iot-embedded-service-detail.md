# US-009: IoT & Embedded Service Detail

## User Story

**As an** IoT product manager evaluating hardware-software consulting options (P-004),
**I want to** read a dedicated page about Keith's IoT & Embedded services with specific technology experience listed,
**So that** I can quickly assess whether his background matches my firmware/protocol stack before scheduling a call.

## Acceptance Criteria

- [ ] Given a visitor navigates to the IoT & Embedded service section or detail page, when the content renders, then specific embedded platforms, protocols (e.g., MQTT, BLE, Zigbee), and firmware languages are listed.
- [ ] Given an IoT PM reads the page, when reviewing the content, then at least one concrete example project or outcome is described.
- [ ] Given the IoT service page is linked from the services overview (US-002), when a visitor arrives via that link, then the page is clearly scoped to IoT/Embedded work.
- [ ] Given a visitor reads the page, when they decide to inquire, then a CTA links to the contact form (US-011) with IoT pre-filled as the service type.

## Notes

This is a niche differentiator that few fractional CTOs offer. Specificity is important — vague claims about "hardware experience" won't resonate with P-004. Could be a modal/drawer off the services page in v1 instead of a full separate route. Related: US-002 (services overview), US-011 (contact form).
