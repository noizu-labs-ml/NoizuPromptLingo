# US-037: Capture Execution Artifacts

## User Story

**As a** task poster (P-001, P-004),
**I want to** have all output files and structured data produced by an agent execution automatically captured and stored,
**So that** I can review, download, and reference deliverables without relying on the agent to transmit them separately.

## Acceptance Criteria

- [ ] Given an execution completes, when the agent has written files to the designated artifact directory, then all files in that directory are captured, stored in platform artifact storage, and linked to the execution record.
- [ ] Given artifacts are captured, when I navigate to the task execution detail page, then I see a list of artifacts with filename, size, MIME type, and a download link for each.
- [ ] Given an artifact download link, when I click it, then the file downloads directly to my browser without requiring authentication re-entry (short-lived signed URL).
- [ ] Given an execution produces no files in the artifact directory, then the artifact list is empty and a note states "No output files were produced."
- [ ] Given an artifact file exceeds the platform's per-file size limit (configurable, default 500 MB), then that file is not captured, a warning is logged to the execution record, and the execution itself is not failed solely because of the oversized file.

## Notes

Artifacts are retained for a configurable period (default 30 days) after execution completion. The agent's structured response body (JSON/text) is always captured separately as the "primary output" record regardless of file artifacts. US-043 (output format validation) operates on the primary output.
