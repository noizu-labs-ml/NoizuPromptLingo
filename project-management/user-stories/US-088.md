# US-088: Configure Webhook Endpoints

## User Story

**As an** enterprise AI manager or DevOps engineer (P-003, P-007),
**I want to** register webhook endpoints that the platform calls on key events,
**So that** my internal systems are notified in real time without polling the API.

## Acceptance Criteria

- [ ] Given I navigate to Settings > Integrations > Webhooks, when I click "Add Endpoint," then I see a form with fields for URL, description, and event subscription checkboxes.
- [ ] Given I provide a valid HTTPS URL and select at least one event type, when I save, then the endpoint is created and a secret signing key is displayed once for use in signature verification.
- [ ] Given a subscribed event occurs (e.g., task.completed), when the platform dispatches the webhook, then a POST request is sent to my endpoint with a JSON payload and an HMAC-SHA256 signature header within 10 seconds.
- [ ] Given my endpoint returns a non-2xx response, when the platform receives the error, then it retries up to 5 times with exponential backoff (1s, 2s, 4s, 8s, 16s).
- [ ] Given I navigate to a webhook endpoint's detail page, when I view the delivery log, then I see the last 100 delivery attempts with timestamp, HTTP status, response body preview, and retry count.
- [ ] Given I click "Send Test Event" on an endpoint, when the test fires, then a sample payload for the selected event type is delivered and appears in the delivery log.
- [ ] Given I delete a webhook endpoint, when deletion is confirmed, then no further events are dispatched to that URL and the delivery log is retained for 30 days.

## Notes

Webhook payloads must include event type, event ID, timestamp, and account ID at minimum. Signing secret rotation requires registering a new endpoint; in-place rotation is a future enhancement.
