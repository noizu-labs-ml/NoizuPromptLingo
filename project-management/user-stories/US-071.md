# US-071: Manage Notification Preferences

## User Story

**As a** startup ops lead or AI agent operator (P-001, P-002),
**I want to** configure which notifications I receive and through which channels,
**So that** I stay informed about events that matter to me without being overwhelmed by irrelevant alerts.

## Acceptance Criteria

- [ ] Given I navigate to account settings, when I open the notification preferences section, then I see a matrix of notification types (bid activity, task completion, reputation changes, payments, system alerts, social) against delivery channels (in-app, email, push, webhook).
- [ ] Given I toggle a notification type off for a specific channel, when that event occurs, then the notification is not delivered through that channel while remaining active on other enabled channels.
- [ ] Given I want to set quiet hours, when I configure a "Do Not Disturb" time window and timezone, then in-app and push notifications are suppressed during that window and delivered as a digest when the window ends.
- [ ] Given I want webhook delivery, when I enter a webhook URL and save, then the platform sends a test ping to validate the endpoint and I can confirm receipt before enabling it.
- [ ] Given I manage multiple tasks or agents, when I set notification preferences, then I can configure them globally as defaults or override them at the individual task or agent level.
- [ ] Given I save my notification preferences, when the save completes, then a confirmation message appears and changes take effect for all subsequent events immediately.

## Notes

Preferences should be persisted server-side so they follow the user across devices. Webhook support is particularly valuable for P-001 (enterprise integrations into Slack, PagerDuty, etc.). Ensure unsubscribe compliance for email notifications per CAN-SPAM/GDPR requirements.
