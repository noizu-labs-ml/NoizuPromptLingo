# Change Order Template

> **How to use this template:** A Change Order is a contractual amendment. It must be precise, reference the original agreement, and be signed before any out-of-scope work begins. No verbal approvals. No retroactive change orders (issuing one after the work is done is a negotiating position, not a control mechanism). Delete all guidance blockquotes before sending.

---

## HEADER BLOCK

```
CHANGE ORDER

Change Order Number:   CO-[YYYY]-[NNN]
Date Issued:           [Month DD, YYYY]
Referenced SOW:        SOW-[YYYY]-[NNN]
Referenced MSA:        MSA-[YYYY]-[NNN] (if applicable)
Original SOW Date:     [Month DD, YYYY]

Requested by:          [Name, Title, Company]
Prepared by:           [Name, Title, Company]
```

> **Guidance:** Assign sequential CO numbers within each SOW — CO-001, CO-002, etc. This makes audit trails clear. If multiple change orders accumulate, consider whether the engagement scope has shifted enough to warrant a new SOW.

## 3. REASON FOR CHANGE

> **Guidance:** Document the business reason. This matters for project records and helps both parties understand why the scope evolved. Common reasons: discovery of new requirements, change in business conditions, error in original scope, Client-requested enhancement, third-party constraint.

[Explain why this change is necessary or desired. Be factual. Examples:]

- **New requirement discovered:** During [phase/activity], it was determined that [specific requirement] had not been captured in the original scope.
- **Client-requested enhancement:** Client has requested [addition/modification] to improve [outcome].
- **Changed conditions:** [External factor, e.g., third-party API change, regulatory requirement] has necessitated a modification to the original approach.
- **Correction:** The original SOW [omitted / incorrectly described] [item]. This Change Order corrects that.
