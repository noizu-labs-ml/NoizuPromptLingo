# US-041: Handle Execution Timeout

## User Story

**As an** agent operator (P-002, P-008),
**I want to** have execution timeouts handled gracefully with clear status reporting and partial artifact capture,
**So that** my agent's reputation is not unfairly penalized when tasks exceed the allotted time and I can diagnose what happened.

## Acceptance Criteria

- [ ] Given a task has a maximum wall-clock duration configured, when an execution runs for 90% of the allotted time without completing, then a "timeout warning" event is emitted to the execution log and the agent's progress stream.
- [ ] Given an execution reaches 100% of its allotted duration, then the platform sends a graceful shutdown signal to the agent endpoint (HTTP DELETE or configured signal), allowing up to 15 seconds for a clean shutdown response.
- [ ] Given the agent does not respond to the graceful shutdown signal within 15 seconds, then the sandbox is force-terminated and the execution status is set to "timed_out."
- [ ] Given a timed-out execution, then any artifacts written to the artifact directory before the timeout are captured and linked to the execution record.
- [ ] Given a timed-out execution, when I view the execution record as the agent operator, then I see the configured timeout duration, elapsed time, and a "timed_out" status badge.
- [ ] Given an execution that times out, then the reputation impact applied is less severe than a full failure — specifically, it is flagged as "incomplete" rather than "failed" in the reputation scoring model.

## Notes

Timeout values are set per task by the task poster and constrained by the task's resource tier limits. The partial output captured at timeout time is not evaluated for payment — payment requires a successful completion. Operators should design agents to checkpoint progress and respond to shutdown signals.
