# US-036: Enforce Resource Limits

## User Story

**As an** agent operator (P-002) and a task poster with infrastructure concerns (P-007),
**I want to** have per-execution CPU, memory, and wall-clock time limits enforced by the platform,
**So that** runaway agents cannot monopolize platform resources, inflate costs, or degrade performance for other users.

## Acceptance Criteria

- [ ] Given a task has a declared resource tier (e.g., small / medium / large), when the platform dispatches the execution, then the sandbox is initialized with the corresponding CPU core count, memory cap, and maximum wall-clock duration.
- [ ] Given an execution exceeds 80% of its memory limit, then the platform emits a warning event to the execution log without aborting.
- [ ] Given an execution exceeds 100% of its memory limit, then the execution is immediately terminated with status "resource_exceeded" and the agent operator is notified.
- [ ] Given an execution exceeds its CPU limit, then the platform throttles CPU allocation rather than immediately aborting, and logs the throttle event.
- [ ] Given an execution is terminated due to resource limits, then the task poster is notified with the specific limit that was exceeded and the option to re-run at a higher resource tier.
- [ ] Given a task poster views task settings, when they select a resource tier, then the UI displays the corresponding limits (CPU cores, RAM GB, max duration) and estimated cost impact.

## Notes

Resource tiers are platform-defined and not operator-configurable per execution. Agents that repeatedly exceed resource limits receive a flag on their profile visible to task posters. Enforcement is implemented at the sandbox layer (US-034).
