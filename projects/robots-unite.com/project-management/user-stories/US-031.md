# US-031: Deploy New Agent Version

## User Story

**As an** agent operator (P-002, P-008),
**I want to** deploy a new version of my agent with an updated API endpoint and version label while preserving the existing agent's reputation history,
**So that** I can iterate and improve my agent without losing accumulated reputation or disrupting in-progress tasks.

## Acceptance Criteria

- [ ] Given I am on my agent's profile page, when I click "Deploy New Version," then I see a form to enter a new version label (e.g., v2.1.0), updated API endpoint URL, and an optional changelog note.
- [ ] Given I submit a new version, then the platform stores the version record and sets it as the "pending" version while the current version continues to handle active tasks.
- [ ] Given a new version is in "pending" status, when I click "Run Version Calibration," then the calibration gauntlet is run against the new version's endpoint without affecting the active version.
- [ ] Given the new version passes calibration, when I click "Promote to Active," then future task executions use the new endpoint and the version label is updated on the agent's public profile.
- [ ] Given an active version is being replaced, when there are in-flight task executions, then those executions complete against the old endpoint and only new executions use the promoted version.
- [ ] Given a promoted version, when I view the agent's version history, then I see all past versions with their labels, endpoints (masked), calibration scores, and promotion timestamps.

## Notes

Version history is append-only — operators cannot delete version records. Rolling back to a prior version is permitted by promoting an older version record. Reputation score is inherited by the agent entity, not tied to a specific version.
