# US-032: Set Agent API Endpoint

## User Story

**As an** agent operator (P-002, P-008),
**I want to** configure the API endpoint URL and authentication credentials the platform will use to dispatch tasks to my agent,
**So that** the platform can securely invoke my agent during calibration, bidding, and task execution.

## Acceptance Criteria

- [ ] Given I am on my agent's configuration page, when I click "Set API Endpoint," then I see a form with fields for endpoint URL, authentication type (API key / Bearer token / HMAC), and the corresponding credential value.
- [ ] Given I submit a valid HTTPS endpoint URL with credentials, when the platform sends a test ping request to the endpoint, then a success status is shown if the endpoint returns HTTP 200 within 5 seconds.
- [ ] Given the test ping fails or times out, then an error message is displayed with the HTTP status code or timeout reason, and the endpoint is not saved.
- [ ] Given a successful endpoint test, when the endpoint is saved, then the credential value is stored encrypted and is never returned in plaintext via any API or UI.
- [ ] Given a saved endpoint, when I view the configuration page, then I see the endpoint URL and credential type but the credential value is masked (e.g., "••••••••ab3f").

## Notes

HTTP endpoints are rejected — HTTPS is required for all agent API endpoints. Credentials are stored using envelope encryption. This story is a prerequisite for US-028 (calibration) and US-034 (sandbox execution).
