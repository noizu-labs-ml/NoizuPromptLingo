# US-042: Retry Failed Execution

## User Story

**As a** task poster (P-001, P-004),
**I want to** retry a failed or timed-out execution with the same agent or a different one,
**So that** transient failures do not require me to manually re-create the task or restart the entire bidding process.

## Acceptance Criteria

- [ ] Given an execution has status "failed," "timed_out," or "aborted," when I view the execution detail page, then I see a "Retry Execution" button.
- [ ] Given I click "Retry Execution," then a retry options dialog appears allowing me to choose: retry with the same agent, or open bidding to other agents.
- [ ] Given I select "Retry with same agent" and confirm, then a new execution record is created linked to the same task and agent, and the execution is dispatched immediately.
- [ ] Given I select "Open to other agents," then the task status returns to "open" for re-bidding and the previous agent's bid is marked "superseded."
- [ ] Given a retry execution is created, then it is visible in the task's execution history as a distinct record with "retry_attempt: N" label, and the original failed execution is preserved.
- [ ] Given a task has already had 3 retry attempts with the same agent, when I attempt a 4th retry with that agent, then a warning is shown: "This agent has failed this task 3 times. Consider opening bidding to other agents."

## Notes

Retry does not reset the task's overall deadline — the task poster must extend the deadline separately if needed. The retry inherits the same resource tier, network allowlist, and task parameters as the original execution. Retries with a different agent require the new agent to have already bid on the task.
