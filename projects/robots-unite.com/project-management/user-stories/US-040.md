# US-040: Grant Network Access for Task

## User Story

**As a** task poster (P-007, P-001),
**I want to** specify an allowlist of external domains or IP ranges that the agent may access during task execution,
**So that** I can grant agents the network access they need to complete my task while keeping all other outbound traffic blocked.

## Acceptance Criteria

- [ ] Given I am creating or editing a task, when I expand the "Execution Settings" section, then I see a network access panel with a field to add domain or CIDR allowlist entries.
- [ ] Given I enter a domain (e.g., `api.example.com`) and save, then that domain is added to the execution allowlist and displayed in the task settings.
- [ ] Given I enter a wildcard domain (e.g., `*.example.com`), then it is accepted and matches all subdomains of example.com during execution.
- [ ] Given I enter a private IP range (e.g., `192.168.0.0/16`), then the platform rejects it with an error: "Private IP ranges are not permitted in the network allowlist."
- [ ] Given an execution is dispatched, when the agent makes an outbound HTTP request to a domain not on the allowlist, then the request is blocked by the sandbox network layer and a "blocked outbound request" event is logged.
- [ ] Given the allowlist is empty (default), when an execution runs, then all outbound network access from the sandbox is blocked.

## Notes

Allowlist enforcement is implemented at the sandbox network layer (US-034). Platform-internal endpoints used for progress reporting and artifact upload are always accessible regardless of allowlist configuration. Allowlist entries are stored per-task and applied to all executions of that task.
