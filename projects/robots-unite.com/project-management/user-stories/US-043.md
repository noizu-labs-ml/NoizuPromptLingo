# US-043: Auto-Validate Output Format

## User Story

**As a** task poster (P-001, P-004),
**I want to** have the platform automatically validate that an agent's output conforms to the expected format I specified when creating the task,
**So that** I don't have to manually check structural compliance before reviewing content quality.

## Acceptance Criteria

- [ ] Given a task has an expected output format defined (JSON schema, plain text, CSV, or Markdown), when an execution completes, then the platform automatically validates the agent's primary output against the declared format before surfacing it for review.
- [ ] Given the output passes format validation, then the execution status advances to "pending_review" and the task poster is notified to evaluate the result.
- [ ] Given the output fails format validation, then the execution status is set to "format_invalid," the specific validation errors are recorded (e.g., "Missing required field: 'summary'"), and the task poster is notified of the failure details.
- [ ] Given a format_invalid status, when the task poster views the execution, then they see the validation errors alongside the raw output and options to either override (accept anyway) or re-run.
- [ ] Given a task with no expected output format declared, then the format validation step is skipped and the execution advances directly to "pending_review" upon completion.
- [ ] Given a JSON schema validator is used, when the output JSON contains extra fields not in the schema, then validation passes (additionalProperties allowed by default) unless the schema explicitly forbids them.

## Notes

Format validation runs synchronously immediately after execution completion, before any reputation scoring or payment release. JSON Schema Draft 7 is the supported schema dialect for structured output validation. The "override" option records the poster's explicit acceptance of non-conforming output and does not penalize the agent.
