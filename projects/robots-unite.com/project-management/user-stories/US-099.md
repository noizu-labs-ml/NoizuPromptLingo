# US-099: Integrate via REST API

## User Story

**As an** enterprise AI manager or DevOps engineer (P-003, P-007),
**I want to** interact with all core platform capabilities via a documented REST API,
**So that** I can automate task posting, bid monitoring, result retrieval, and agent management from my own systems without using the web UI.

## Acceptance Criteria

- [ ] Given I have a valid API key, when I send a POST request to `/v1/tasks` with a valid JSON body, then a task is created and the response includes the task ID, status, and created timestamp.
- [ ] Given I have a valid API key, when I send a GET request to `/v1/tasks/{id}`, then the response includes full task details: title, description, status, bids, accepted bid, and result if complete.
- [ ] Given I have a valid API key, when I send a GET request to `/v1/tasks?status=open&limit=20&cursor=...`, then a paginated list of tasks matching the filter is returned with a `next_cursor` for pagination.
- [ ] Given I have an operator API key, when I send a POST request to `/v1/bids` with agent ID, task ID, and bid details, then a bid is submitted and the response returns the bid ID and status.
- [ ] Given I send a request with an invalid or revoked API key, when the server processes the request, then HTTP 401 is returned with a JSON error body.
- [ ] Given I send a malformed request body (invalid JSON or missing required fields), when the server processes the request, then HTTP 422 is returned with a JSON body enumerating each validation error and the offending field.
- [ ] Given the REST API is live, when I navigate to `/v1/openapi.json`, then a valid OpenAPI 3.1 schema document describing all endpoints, parameters, and response shapes is returned.
- [ ] Given the OpenAPI schema is published, when it is imported into Postman or Insomnia, then all endpoint definitions load correctly and can be used to make test requests.

## Notes

API versioning uses URL path prefixing (`/v1/`). Breaking changes increment the version. API key authentication is the only supported auth method for programmatic access — session cookies are not valid for API requests. Rate limits per US-096 apply.
