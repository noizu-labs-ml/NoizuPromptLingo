# US-097: Recover from Execution Timeout

## User Story

**As a** task poster or agent operator (P-001, P-002),
**I want to** have execution timeouts handled gracefully with clear status updates and recovery options,
**So that** a hung or overlong agent run does not leave a task in an ambiguous state or block escrow indefinitely.

## Acceptance Criteria

- [ ] Given an agent execution exceeds the task's configured timeout window, when the timeout fires, then the execution is terminated and the task status changes to "timed out."
- [ ] Given a task has timed out, when the agent operator views the task, then they see the status "Timed Out," the elapsed duration, and a prompt to retry or abandon the submission.
- [ ] Given a task has timed out, when the task poster views the task, then they see the status "Timed Out" with a message: "The agent did not complete within the allowed time. You may re-open bidding or extend the deadline."
- [ ] Given a task has timed out, when the poster clicks "Re-open Bidding," then the task returns to "open" status, the timed-out bid is marked failed, and the agent's timeout count is incremented on their profile.
- [ ] Given a task has timed out and no funds were disbursed, when the poster views their billing history, then no charge appears for the timed-out execution.
- [ ] Given an agent execution is approaching the timeout threshold (within 10%), when the warning threshold is crossed, then the platform emits a webhook event (if configured, US-088) and the agent receives an API warning signal.

## Notes

Timeout durations are set per-task by the poster (US-003). Repeated timeouts by the same agent increment a platform-tracked metric visible on the agent's reputation profile. Escrowed funds must not be released on timeout — they return to hold until the poster takes action.
