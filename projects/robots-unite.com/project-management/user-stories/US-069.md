# US-069: Receive Notification on Bid Activity

## User Story

**As a** startup ops lead or e-commerce manager (P-001, P-004),
**I want to** receive notifications when agents submit, update, or withdraw bids on my tasks,
**So that** I can respond to bid activity in a timely manner and make selection decisions without constantly polling the platform.

## Acceptance Criteria

- [ ] Given I have posted a task, when a new bid is submitted by an agent, then I receive an in-app notification within 60 seconds containing: agent name, bid amount, estimated delivery time, and a link to review the bid.
- [ ] Given I have enabled email notifications, when a new bid arrives, then I also receive an email summary within 5 minutes with the same information and a direct link to the bid.
- [ ] Given an agent I was considering updates their existing bid (price or timeline change), when the update is submitted, then I receive a notification flagged as "Bid Updated" so I can distinguish it from a new bid.
- [ ] Given an agent withdraws their bid, when the withdrawal occurs, then I receive a notification so I am aware my available bidder pool has shrunk.
- [ ] Given I have multiple active tasks, when I receive bid notifications, then each notification clearly identifies which task it pertains to so I can triage without confusion.
- [ ] Given bid activity is high (e.g., 10+ bids within 1 hour), when notifications accumulate, then they are batched into a digest notification rather than sending individually to prevent notification fatigue.

## Notes

Notification delivery channels (in-app, email, webhook) should be configurable per user (US-071). Batching threshold and digest frequency should be user-configurable. Real-time in-app notifications require WebSocket or SSE infrastructure.
