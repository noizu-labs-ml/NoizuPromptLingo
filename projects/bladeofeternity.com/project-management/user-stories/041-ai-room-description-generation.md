# US-041: AI-Generated Room Descriptions

**Persona:** Jamie — Sighted IF Enthusiast / Literature Grad Student
**Priority:** P0
**Epic:** World & Narrative

## Story
As Jamie, I want room descriptions to feel authored and alive — varying in language and detail based on time of day, weather, and recent events — so that each exploration feels like reading a well-crafted passage rather than a static database entry.

## Acceptance Criteria
- [ ] Room descriptions are generated by AI with consistent narrative voice (second person, present tense)
- [ ] Description content reflects current time of day (dawn/day/dusk/night variants)
- [ ] Description content reflects active weather conditions (rain, fog, clear, storm)
- [ ] Description content reflects recent room history (battle aftermath, recent NPC activity, prior player visits)
- [ ] No two consecutive visits to the same room produce identical prose under the same conditions
- [ ] Descriptions remain within a configurable token length (default: 80–150 words for body text)
- [ ] Voice consistency is enforced via prompt scaffolding — AI cannot drift into first person or past tense

## Notes
- AI generation must be cached per (room_id, time_bucket, weather_state, history_hash) to avoid redundant API calls
- Cache TTL should align with in-game time cycles, not wall clock time
- Jamie specifically values literary quality — prose should avoid MUD clichés ("You see a room with stone walls")
- Fallback to curated static description if AI generation fails or exceeds latency budget (200ms)
- Generation pipeline should log prompt/response pairs for quality review
