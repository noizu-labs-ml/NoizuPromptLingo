# US-055: Graceful crash recovery on restart

As a knowledge-worker,
I want the application to recover gracefully after an unexpected crash,
so that my clipboard history is preserved and I can resume normal operation.

## Scenario: Auto-detect previous crash on startup
Given Smart Clipboard crashed the last time it was running
When I restart the application
Then the app should detect the abnormal termination and log the event

## Scenario: Preserve clipboard items from crashed session
Given the application crashed during operation
When the application restarts
Then all clipboard items from the crashed session should be preserved and accessible

## Scenario: Offer to report crash to developer
Given the application is starting after a crash
When crash analytics and reporting is enabled
Then the startup sequence should briefly display "Unexpected shutdown detected" with an option to send a crash report

## Scenario: Recover unsaved clipboard item
Given the application crashed after detecting a clipboard change but before saving to database
When the application restarts
Then the app should check the current system clipboard and offer to save any content found there

## Scenario: Restart clipboard monitoring after recovery
Given the application crashed while monitoring clipboard
When the application restarts and recovers
Then clipboard monitoring should resume automatically without requiring user action

## Scenario: Maintain sync consistency after crash
Given the application crashed during a sync operation
When the application restarts
Then the sync system should verify consistency with the sync target and reconcile any partial updates

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Some clipboard content may be lost if crash happened between change detection and save; need robust state recovery
- **Dependencies**: US-022, US-023, US-030
