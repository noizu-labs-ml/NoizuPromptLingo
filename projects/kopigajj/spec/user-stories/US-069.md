# US-069: Context-Aware Suggestions

As a developer,
I want the clipboard manager to suggest relevant items based on my current context (active app, time of day, usage patterns),
so that I can access the most likely needed content without searching.

## Scenario: Suggest based on active application
Given the user switches from Chrome to Xcode and opens the clipboard popup
When the popup appears
Then items previously copied in Xcode or related development tools should appear at the top
And the relevant source should be clearly indicated

## Scenario: Time-based pattern suggestions
Given the user frequently copies specific content at certain times (e.g., daily meeting notes at 10 AM)
When the user opens the clipboard near that time
Then recently used items from similar time windows should be suggested prominently
And suggestions should include a note like "Frequently used at this time"

## Scenario: Suggest based on current project or domain
Given the clipboard history contains items from multiple projects (e.g., "Project A API key", "Project B URL")
When the user is working in a context associated with Project A (e.g., app from Project A is active)
Then items tagged or associated with Project A should be prioritized in suggestions

## Scenario: Suggest duplicates of recently copied content
Given the user copies an email address and pastes it multiple times in succession
When the user opens the clipboard popup shortly after
Then the recently pasted item should be prominently displayed as "Recent Use"
And keyboard shortcuts should allow quick selection of the previous copied item

## Scenario: Contextual action suggestions
Given the user is working in an app that typically requires URLs (e.g., a browser)
When the clipboard popup is open
Then URL-type items should be visually emphasized or grouped
And quick actions like "Open in Browser" should be more accessible

## Scenario: Learn from dismissal patterns
Given the user frequently dismisses or ignores certain types of suggestions
When suggestion heuristics run
Then the algorithm should deprioritize those content types or contexts for that user
And suggestion accuracy should improve over time

## Scenario: Workspace-specific suggestions
Given the user has defined multiple workspaces or contexts (e.g., "Personal", "Work", "Side Project")
When the workspace switcher indicates a specific workspace
Then clipboard items from that workspace should be prioritized in suggestions
And cross-workspace items should be less visible

## Scenario: Suggest based on clipboard content relationships
Given the user copied a JSON snippet 5 minutes ago and now copies an HTTP URL
When the popup is accessed
Then items related to API development (JSON, URLs) should be grouped
And suggestions should reflect the current "session" of related copies

## Scenario: Confidence indicators for suggestions
Given suggestions may not always be accurate
When contextual suggestions are displayed
Then a visual indicator should show suggestion confidence (e.g., "Based on active app: Xcode" with high/medium/low confidence)
And users should be able to disable suggestions or adjust sensitivity

## Scenario: Per-app context rules
Given the user wants more granular control
When the user accesses preferences
Then per-application context rules should be configurable (e.g., "When in Terminal, prioritize recent commands")
And users should be able to define custom rules

## Notes
- **Persona**: developer
- **T-Shirt Size**: XL
- **Complexity**: very-high
- **Risks**: Inaccurate suggestions could be frustrating; privacy concerns with tracking context; complex heuristics; performance impact
- **Dependencies**: US-001 (global hotkey), US-004 (clipboard history display), US-014 (content type detection)
