# US-107: Chord Navigation State Machine

As a developer,
I want the UI to manage keyboard state transitions between panels and modes,
so that keyboard interactions are predictable and consistent.

## Scenario: Idle to History Panel transition
Given the application is in idle state (no panels open)
When the user presses Cmd+Shift+T V
Then the history panel should open with first entry selected
And state should transition to HistoryPanel mode

## Scenario: History Panel to Idle transition
Given the history panel is open
When the user presses Escape
Then the panel should close
And state should transition to Idle

## Scenario: History Panel to Variable Form transition
Given a macro with variables is selected
When the user presses Enter
Then the variable form should open
And state should transition to VariableForm mode

## Scenario: Variable Form to Idle transition
Given the variable form is open
When the user presses Escape without pasting
Then the form should close and return to history panel
And state should transition back to HistoryPanel (not directly to Idle)

## Scenario: LLM Fill state transition
Given the variable form is open
When the user presses Cmd+Shift+T A (LLM fill)
Then the LLM fill state should be activated
And completion should return to VariableForm mode

## Scenario: State persistence for re-opening
Given a panel was open when dismissed
When the same panel is re-opened shortly after
Then the previous selection state should be retained
And scroll position should be preserved

## Scenario: Concurrent panel prevention
Given a panel is currently open
When the user tries to open a different panel
Then the current panel should close first
Then the new panel should open
Or the action should be denied with feedback

## Notes
- **Persona**: developer
- **T-Shirt Size**: XL
- **Complexity**: high
- **Risks**: State bugs, lost state transitions, edge cases with rapid key presses
- **Dependencies**: All keyboard navigation related user stories (US-100 through US-106)
