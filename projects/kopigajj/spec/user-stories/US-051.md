# US-051: Recovery from corrupted history file

As a knowledge-worker,
I want the application to recover from corrupted clipboard history files,
so that I don't lose my entire history due to a single corrupted entry.

## Scenario: Detect corrupted clipboard item
Given a clipboard history file contains one or more corrupted items
When the application loads the history
Then the app should skip corrupted items and complete loading with valid items

## Scenario: Exclude corrupted items from visible history
Given a corrupted item was detected and skipped during load
When I view the clipboard history popup
Then the corrupted item should not appear in the visible history

## Scenario: Log corrupted item details for repair
Given a corrupted item was detected
When the application processes the file
Then details of the corrupted item (file path, error) should be logged for potential manual repair

## Scenario: Attempt recovery of corrupted item content
Given an item appears corrupted during load
When I select "Attempt Repair" for that entry
Then the app should try to recover partial content and make what is available accessible

## Scenario: Backup corrupted file before recovery attempt
Given a clipboard history file is identified as corrupted
When the app begins recovery operations
Then the original corrupted file should be copied with a ".backup" extension before modification

## Scenario: Report corruption summary to user
Given one or more corrupted items were detected during load
When the application starts
Then a notification should appear indicating that X clipboard items could not be loaded and were skipped

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Incorrect detection could mark valid content as corrupted; need careful error handling
- **Dependencies**: US-031, US-050
