# US-070: Usage Statistics Dashboard

As a knowledge-worker,
I want to see statistics about my clipboard usage patterns,
so that I can understand my workflow and potentially optimize how I use the clipboard manager.

## Scenario: View overall usage statistics
Given the user has been using Smart Clipboard for at least one week
When the user opens the Usage Statistics dashboard from preferences
Then they should see: total items copied, average daily copies, most active time of day, and most copied content types

## Scenario: Display top most-copied items
Given the clipboard history contains many items with varying frequency
When the user views the statistics dashboard
Then a list of the top 10 most-copied items should be displayed with copy count and last copied date
And duplicate variants should be aggregated

## Scenario: Content type breakdown chart
Given the clipboard history contains various content types (text, URLs, JSON, images)
When the user views statistics
Then a breakdown should show the percentage for each content type
And a visual chart or bar graph should represent the distribution

## Scenario: Temporal usage visualization
Given the user wants to understand their usage patterns over time
When they view daily, weekly, or monthly usage stats
Then a timeline graph should show copy frequency over the selected period
And identifiable patterns (e.g., peak usage hours) should be highlighted

## Scenario: Source application ranking
Given the application tracks which apps were the source of clipboard copies
When the user views statistics
Then the top 5 source applications should be listed with copy counts
And the percentage of total copies for each app should be shown

## Scenario: Search query analytics
Given the user frequently searches their clipboard history
When they view usage statistics
Then top search terms and search frequency should be displayed
And search success rate (results found vs. no results) should be shown

## Scenario: Privacy-aware statistics
Given some users may be concerned about data collection
When statistics are enabled
Then all statistical data should remain local and never be transmitted
And users should be able to completely disable statistics collection

## Scenario: Export statistics data
Given the user wants to analyze their clipboard usage externally
When the user clicks "Export Statistics" from the dashboard
Then a CSV or JSON file should be generated with all available statistical data
And the user should be prompted for a save location

## Scenario: Reset statistics
Given the user wants to fresh-start their usage tracking
When they click "Reset Statistics" from the dashboard
Then a confirmation dialog should appear warning that data will be lost
And upon confirmation, all statistics should be cleared while preserving clipboard history

## Scenario: Periodic summary insights
Given the user has accumulated a month of usage data
When they view the statistics dashboard
Then automatically generated insights should appear (e.g., "Your clipboard usage increased 25% this week", "Most active day: Tuesday")
 And these insights should help users understand their patterns

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Privacy concerns with usage tracking; storage overhead for statistics data; UI clutter if too much information displayed
- **Dependencies**: US-004 (clipboard history display), US-062 (database schema)
