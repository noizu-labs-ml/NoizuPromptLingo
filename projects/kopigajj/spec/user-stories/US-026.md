# US-026: Client-side encryption for sync data

As a developer,
I want clipboard data to be encrypted on-device before syncing,
so that my clipboard history is never stored in plaintext on the sync server.

## Scenario: Encrypt clipboard item before upload
Given I have clipboard items to sync
When the sync process prepares data for upload
Then each clipboard item should be encrypted using the configured key before being sent to the server

## Scenario: Decrypt clipboard item after download
Given I receive encrypted clipboard items from the sync server
When the sync process processes downloaded data
Then each clipboard item should be decrypted using the configured key before being stored locally

## Scenario: Sync with missing encryption key
Given encrypted data exists on the sync server
When a device attempts to sync without an encryption key
Then the sync should fail with a clear error message indicating that the encryption key is required

## Scenario: Verify encrypted server storage
Given I have synced clipboard items
When I inspect the data stored on the sync server directly
Then the clipboard content should be encrypted and not readable in plaintext

## Scenario: Key rotation with existing data
Given encrypted data exists on the sync server with an old key
When I change my encryption key
Then existing data should be downloaded, decrypted with the old key, re-encrypted with the new key, and re-updated to the server

## Notes
- **Persona**: developer
- **T-Shirt Size**: XL
- **Complexity**: very-high
- **Risks**: Encryption must be auditable; key loss means data loss; performance impact
- **Dependencies**: US-022, US-025
