# US-031: Handle large clipboard content (>10MB)

As a knowledge-worker,
I want the app to handle large clipboard items gracefully,
so that copying large content doesn't crash or freeze the application.

## Scenario: Store large text content
Given I copy text that exceeds 10MB from a text editor
When the clipboard change notification is received
Then the content should be stored in the database with a reference to a separate large content storage mechanism

## Scenario: Display truncated preview of large content
Given a clipboard item contains >10MB of content
When the item appears in the history popup
Then only the first 1KB should be displayed as a preview with an indicator showing "(truncated)"
When I select the item, the full content should be pasted to the clipboard

## Scenario: Option to exclude large items
Given I copy content that is >10MB
When the " Exclude items larger than" setting threshold is exceeded
Then the item should not be stored in history, or should be stored with only metadata without the full content

## Scenario: Memory-efficient loading of large items
Given I have a clipboard history with multiple large items
When I navigate through the history
Then large items should only be loaded into memory when actually needed (lazy loading)

## Scenario: Clean up old large items
Given the database contains large clipboard items that exceed the configured retention age
When retention cleanup runs
Then old large items should be removed from both the database and large content storage

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Large files can exhaust memory and disk quickly; storage must be managed
- **Dependencies**: US-032
