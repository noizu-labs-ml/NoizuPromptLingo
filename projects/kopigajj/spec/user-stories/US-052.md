# US-052: Graceful handling of sync network outages

As a knowledge-worker,
I want the application to handle sync network failures gracefully,
so that I can continue using clipboard history while offline and sync automatically when connectivity is restored.

## Scenario: Detect network outage during sync
Given sync is and an active sync is in progress
When a network outage occurs
Then the sync should be paused and marked as incomplete with an error logged

## Scenario: Queue unsynced changes during outage
Given a network outage is detected
When I copy new clipboard content
Then the new items should be saved locally and marked as "pending sync" for later transmission

## Scenario: Auto-resume sync when network restored
Given a network outage prevented sync completion
When network connectivity is restored
Then the app should automatically resume and complete the pending sync operation

## Scenario: Show offline indicator to user
Given a sync network outage is active
When I view the menu bar or sync settings
Then an "Offline" or "Network Error" indicator should appear

## Scenario: Manual retry available during outage
Given a network outage is preventing sync
When I view the sync status in settings
Then a "Retry Sync" button should be available but may fail if network is still unavailable

## Scenario: Multiple retry attempts with backoff
Given a sync operation is failing due to network issues
When the app attempts automatic retries
Then retries should use exponential backoff and stop after a configurable maximum attempts (default 5)

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Queue may grow indefinitely during long outages； need merge logic when multiple updates accumulate
- **Dependencies**: US-022, US-023, US-024
