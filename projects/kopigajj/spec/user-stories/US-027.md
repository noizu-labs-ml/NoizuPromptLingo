# US-027: Conflict resolution when devices have divergent history

As a knowledge-worker,
I want to intelligently resolve conflicts when my clipboard histories diverge across devices,
so that I don't lose important clipboard items while maintaining a coherent history.

## Scenario: Simple timestamp-based merge
Given two devices have different clipboard histories with no overlapping changes
When sync is performed
Then the histories should be merged with both devices receiving all items from each other

## Scenario: Detect modification conflict
Given two devices have modified the same clipboard item (same item ID) with different content
When sync is performed
Then the system should detect the conflict and flag both versions

## Scenario: Automatic conflict resolution (newer wins)
Given a conflict is detected but the difference is within one minute
When automatic resolution is enabled
Then the newer item timestamp should be used and the older version discarded

## Scenario: Manual conflict resolution
Given a conflict is detected that cannot be automatically resolved
When I view the conflict resolution dialog
Then I should see both versions side-by-side and can choose which to keep or keep both as separate items

## Scenario: Keep both conflicting items
Given a conflict is detected for the same clipboard item on two devices
When I select "Keep Both"
Then both items should be preserved with distinct IDs and the newer item should be marked as a "conflict resolved" copy

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: L
- **Complexity**: high
- **Risks**: Conflicts can be complex; partial edits need consideration
- **Dependencies**: US-022, US-026
