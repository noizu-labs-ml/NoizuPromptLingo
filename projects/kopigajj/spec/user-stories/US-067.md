# US-067: Smart Duplicate Detection

As a developer,
I want the application to detect and handle duplicate clipboard items intelligently,
so that my clipboard history remains clean and doesn't fill with redundant copies.

## Scenario: Exact duplicate detection
Given the user copies content that exactly matches an existing clipboard item
When the ClipboardMonitor detects the copy
Then the duplicate should be filtered and not added to history
And the existing item's timestamp should optionally be updated

## Scenario: Fuzzy matching for near-duplicates
Given the user copies text with minor differences from an existing item (spacing, trailing whitespace)
When the ClipboardMonitor detects the copy
Then fuzzy matching should detect the similarity within a configurable threshold (e.g., 95% match)
And the near-duplicate should be handled according to user preference (merge, ignore, or keep)

## Scenario: Configurable duplicate behavior
Given different users have different preferences for duplicates
When a user accesses the preferences
Then options should be available to: Show all, Hide exact duplicates, Hide near-duplicates, Merge duplicates
And the setting should apply immediately

## Scenario: Merge multiple variations
Given the clipboard history contains multiple similar but slightly different versions of text
When the user selects "Merge Similar Items"
Then a preview should show the differences (diff view)
And the user can choose which version to keep or create a combined version

## Scenario: Content hashing for efficient comparison
Given a new clipboard item is being processed
When duplicate detection runs
Then a hash (MD5 or similar) should be computed for each item type
And comparison should first check hash equality before expensive content comparison

## Scenario: Image duplicate detection with tolerance
Given the user copies an image with slight modifications (compression artifacts, minor edits)
When duplicate detection runs for images
Then perceptual hash comparison should detect near-duplicates within a similarity threshold
And users should be notified of potential duplicates

## Scenario: Suggest cleanup of duplicates
Given the user has accumulated many duplicates over time
When the user opens preferences or a cleanup utility
Then a summary should show "X exact duplicates and Y near-duplicates found"
And the user should be able to bulk remove them

## Scenario: Duplicate confidence scoring
Given fuzzy matching may have confidence levels
When a near-duplicate is detected
Then the confidence score should be displayed (e.g., "98% similar to item copied 5 minutes ago")
And users can adjust the threshold for what qualifies as a duplicate

## Scenario: Preserve unique but similar items
Given two items are similar but represent genuinely different content
When duplicate detection evaluates them
Then the comparison should consider meaningful differences
And items below the threshold should not be flagged as duplicates

## Notes
- **Persona**: developer
- **T-Shirt Size**: L
- **Complexity**: high
- **Risks**: Fuzzy matching false positives; performance impact on large histories; user confusion about what's considered a duplicate; image hash storage overhead
- **Dependencies**: US-004 (clipboard history display), US-062 (database schema)
