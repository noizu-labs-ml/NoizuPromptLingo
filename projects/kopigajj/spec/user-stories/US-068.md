# US-068: Semantic Search with Natural Language

As a knowledge-worker,
I want to search my clipboard history using natural language queries instead of exact text matches,
so that I can find items even when I don't remember the exact wording.

## Scenario: Natural language query for temporally referenced items
Given the clipboard history contains various items copied over the past week
When the user searches "that API key from yesterday"
Then results should prioritize items copied approximately 24 hours ago containing API key patterns
And the top result should be highlighted as most relevant

## Scenario: Search by descriptive attributes
Given the clipboard contains JSON, URLs, images, and code snippets
When the user searches "JSON from the user service"
Then results should filter to JSON items and rank by presence of "user" keywords
And potentially match source application if available (e.g., from JSON viewer or API tool)

## Scenario: Semantic similarity search
Given the user searches "error message about database"
When the clipboard history contains related text with different wording
Then semantically similar items should be returned (e.g., "Database connection failed", "SQL error: timeout")
And exact word matches should优先 but not exclude semantic matches

## Scenario: Time-based natural language queries
Given the user searches "links copied this morning"
When the search executes
Then only URLs copied today between 6 AM and 12 PM should be returned
And the order should reflect recency

## Scenario: Boolean operators in natural language
Given the user searches "json but not error"
When the search executes
Then results should include JSON items but exclude those containing "error"
And the search should understand the negation syntax

## Scenario: Search result ranking explanation
Given natural language search often has ambiguous results
When search results are displayed
Then each result should show a brief relevance explanation (e.g., "Copied 2 days ago, matches 'API' and 'key'")
And users can toggle between semantic and exact search modes

## Scenario: Auto-suggest based on natural language
Given the user starts typing "copied yesterday"
When the search field is populated
Then autocomplete suggestions should help complete common natural language patterns
And suggestions should prioritize based on clipboard history content

## Scenario: Fallback to exact search for ambiguous queries
Given the user searches a specific string "abc123xyz"
When the exact search would yield highly precise results
Then exact matching should be prioritized over semantic matching
And the user should see a flag indicating "Exact Match" results

## Scenario: Natural language search performance
Given semantic search involves more computation
When the user enters a natural language query
Then results should still appear within 200ms to maintain responsiveness
And search should be debounced to avoid redundant computations

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: XL
- **Complexity**: very-high
- **Risks**: Semantic search accuracy depends on embedding quality; performance overhead; query parsing complexity; user expectations management
- **Dependencies**: US-009 (search functionality), US-062 (database schema - full-text search), US-065 (performance benchmarks)
