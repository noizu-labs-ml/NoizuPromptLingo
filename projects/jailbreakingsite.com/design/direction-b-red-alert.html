// Implementation Checklist

Typography & Color
  • JetBrains Mono as the PRIMARY typeface — headings, IDs, section labels, scan output all mono
  • Inter for body prose, descriptions, and dense UI label text only
  • Two weights: 400 (regular) and 700 (bold mono headings) — 600 only for Inter UI labels
  • Accent (terminal green #34D399) for CTAs, active states, focus rings, pass results, scan progress
  • Severity system (critical/high/medium/low/pass) is the primary visual language of the platform
  • Severity-muted backgrounds for card accents and row highlights — never full-opacity fills
  • Background is 80%+ of visual field — nothing decorative competes with data
  • No gradients, no illustrations, no decorative elements
  • Dark mode only — no light mode toggle
  • Glitch-red (#FF3333) used sparingly: error toast pulse, never in layouts or static states
Layout & Density
  • Max-width 1200px — tighter than Direction A, more ops-console density
  • Sidebar collapses from 220px to 48px icon rail
  • Sidebar structure: logo, catalog nav, research, training, settings (bottom)
  • Attack catalog table as hero surface — sortable, filterable, sticky header
  • Technique detail panel slides in from right (180ms ease-out)
  • Compact table rows: 8px vertical padding, monospace for IDs and timestamps
Components
  • All buttons: 4px radius, monospace font, no shadows on static state
  • Primary button: green glow box-shadow on hover (not static)
  • Danger button: red glow box-shadow on hover (not static)
  • All inputs: 4px radius, 1px border, green focus ring
  • Code input variant uses JetBrains Mono 12px
  • Severity badges: pill-shaped (9999px radius), all uppercase, all monospace, all 11px
  • CRITICAL badge: pulsing dot at 1.8s infinite
  • Technique cards: left-border colored by severity level, mono ID, compact
  • Lab cards: purple left-border and badge, full-width LAUNCH button
  • No border-radius greater than 6px anywhere
Special Effects (Bold Expressive 40%)
  • Glitch animation: CSS keyframe on logo/header hover — horizontal offset + color channel split
  • Glitch uses steps(1) easing — digital, not smooth
  • Glitch MUST respect prefers-reduced-motion (animation disabled via global rule)
  • Terminal block: CRT scan-line via ::before pseudo-element — thin line, slow sweep, low opacity
  • Scan-line also respects prefers-reduced-motion via global rule
  • Error toast: left-border pulses between severity-critical and glitch-red at 3s
  • Scan progress bar animates width from 0% on component mount (2s ease-out)
  • Severity-critical dot: opacity pulse 1.8s infinite — the one persistent Bold Expressive moment
Interaction & Motion
  • 100ms micro-interactions — snappier than Direction A (which uses 150ms)
  • 200ms max for content transitions (panels, toasts)
  • Skeleton loading — no spinners, ever
  • Toast notifications: bottom-right, terminal-style, monospace title all-caps
  • All animations and transitions respect prefers-reduced-motion
  • Keyboard shortcuts: / for search, g+c for catalog, g+l for labs, g+s for scan
Accessibility
  • Color contrast WCAG AA — text-primary #E5E5E5 on bg-primary #0A0A0A (15.1:1)
  • Touch targets ≥ 44px on mobile
  • Severity communicated through label text in addition to color (not color-only)
  • Focus states visible on all interactive elements
  • Terminal block has role="region" and aria-label for screen readers
  • Glitch animation produces no meaningful content loss — decorative only
Do Not
  • No decorative elements, illustrations, or stock photography
  • No gradients — not even subtle ones
  • No border-radius > 6px
  • No spinners — skeletons only
  • No light mode
  • No use of glitch-red outside of explicit Bold Expressive moments (error pulse, glitch keyframe)
  • No sans-serif for technique IDs, scan output, section headings, or data values
