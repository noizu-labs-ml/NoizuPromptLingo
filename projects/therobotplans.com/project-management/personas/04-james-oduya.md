## Bio

James runs a boutique web agency. At any given time, his team juggles 4-6 client projects at different stages. He needs visibility across all of them without drowning in project management overhead. He's currently using ClickUp (which the team hates) and a patchwork of client-specific tools. His biggest pain is context-switching between client worlds and the inability to see cross-project resource allocation.

## Goals

1. **Multi-project portfolio view** — see all active client projects, their health, blockers, and deadlines in one dashboard
2. **Methodology flexibility per project** — one client wants scrum with sprint reviews; another wants kanban; a third just wants a checklist and weekly updates
3. **Agent-generated client reports** — stop spending 2 hours/week writing status emails for each client
4. **Resource allocation visibility** — who's on what, who's overloaded, who has capacity
5. **Templated project setup** — spin up a new client project with standard checklists, wiki structure, and agent config in minutes

## Frustrations

- **ClickUp is a configuration nightmare:** Every project is set up differently because the tool is too flexible without being opinionated
- **No cross-project view that matters:** Can see all projects listed, but can't answer "which project is most at risk this week?" without checking each one
- **Client communication overhead:** 4-6 clients each want weekly updates in their preferred format (email, Slack, Notion page)
- **Onboarding new devs to client projects is slow:** No unified knowledge base per project; tribal knowledge in Slack threads
- **AI features in ClickUp are gimmicks:** Summarize a doc? He can read. He needs AI that manages the project.

## Behaviors

- Monday morning: reviews all projects, identifies risks, allocates team for the week
- Attends 2-3 client standups per week (would prefer agents to handle the rest)
- Tracks agency finances (invoicing, burn rate) separately in Xero
- Uses checklists religiously for deploys, QA, and client handoffs
- Evaluates tools quarterly; switches when the pain exceeds the switching cost

## Job to Be Done

> "I need a tool that lets me run 5 different projects with 5 different methodologies, gives me one dashboard to see what's at risk, and generates client-facing reports so I'm not writing status emails until midnight."

## Key Scenarios

1. **Monday portfolio review:** Opens Reports view. Sees all 5 projects ranked by risk score (agent-computed from overdue items, blocked tasks, SLO burns). Focuses on the two at-risk projects first.
2. **New client onboarding:** Creates project from "Agency Web Build" template. Gets: kanban board, deploy checklist, QA checklist, wiki with architecture doc template, monitor agent watching staging URL. Assigns team members.
3. **Client status report:** PM agent generates: "Project Alpaca, Week 12: 8/10 sprint items complete. Design sign-off pending (blocker). Staging deployed, 0 critical bugs. On track for April 15 launch." James edits slightly and sends.
4. **Cross-project resource conflict:** Team view shows two devs assigned to conflicting deadlines across two projects. James rebalances using drag-and-drop in the capacity planner.

## Product Implications

- **Team tier minimum, likely Business ($59/seat)** for cross-project reporting and custom workflows
- **Project templates** are a power feature for agencies — setup time is money
- **PM agent per project** is the core value prop (each client gets "their own PM")
- **Client-facing report export** (PDF, email, Notion push) is important
- **Multi-org / multi-client isolation** (future feature) is eventually critical for agencies
