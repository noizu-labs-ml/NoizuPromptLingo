## Bio

Diana is an experienced freelancer who works with multiple clients simultaneously. Each client has their own tools (one uses Jira, another Linear, a third uses GitHub Issues). She maintains her own task tracking on top of client systems because she needs a cross-client view of her commitments, deadlines, and billable hours. She's technically sophisticated but exhausted by operational overhead — she wants to code, not project-manage herself across four different tool ecosystems.

## Goals

1. **Cross-client unified view** — see all obligations across 3-4 clients in one surface, with clear deadlines, priorities, and time commitments
2. **Agent-synced client tools** — MCP connectors that pull her assigned tasks from each client's Jira/Linear/GitHub into tobornalp, so she has one inbox instead of four
3. **Time tracking and billable visibility** — know how many hours she's spending per client, flag when she's over/under committed
4. **Personal project runway** — track her own side project (open-source Elixir library) alongside paid work
5. **Financial awareness** — invoicing reminders, contract renewal dates, runway calculations

## Frustrations

- **Four clients = four tools:** She logs into Jira, Linear, GitHub Issues, and Notion daily, each with different workflows and notification settings
- **No unified priority view:** "What's the most important thing across all my clients right now?" requires checking each tool
- **Billable time leaks:** Spends 30+ min/day on tool-switching and status-syncing that she can't bill for
- **Context loss between clients:** Switching from Client A (Elixir API) to Client B (React dashboard) requires mental reboot; no tool helps with the transition
- **Personal project always loses:** Side project gets deprioritized because it's invisible next to paying client work

## Behaviors

- Uses Toggl for time tracking (separate from all task tools — yet another tool)
- Invoices monthly; tracks in a spreadsheet
- Reviews all client commitments on Monday morning; plans the week by client-day blocks
- Prefers async communication; minimizes meetings
- Evaluates tools by "does this reduce my non-billable overhead?"

## Job to Be Done

> "I need one surface that pulls in my tasks from every client's tool, shows me my full week across all commitments, and tracks my time — so I spend less time managing myself and more time billing."

## Key Scenarios

1. **Monday planning:** Opens Today view. MCP connectors have synced: 3 tasks from Client A (Jira), 2 from Client B (Linear), 1 from Client C (GitHub Issues), plus 1 personal side-project item and a dentist appointment. Planner agent suggests day-blocking: "Client A morning (deadline Wednesday), Client B afternoon (PR review due), personal evening."
2. **Client sync conflict:** Two clients both have urgent items due Thursday. Agent flags the conflict Monday and suggests: "Propose Client B deadline slip to Friday — their item has no downstream blockers."
3. **Time tracking integration:** At end of day, agent summarizes: "Client A: 4.5h (billable). Client B: 2h (billable). Tool overhead: 0.5h (non-billable). Side project: 1h." Feeds into invoicing.
4. **Contract renewal reminder:** Agent surfaces: "Client C contract expires in 2 weeks. Last 3 months: avg 15h/week billed. Draft renewal email?"

## Product Implications

- **Pro tier ($14/mo)** — 3 projects (one per active client) + personal
- **MCP connectors to Jira, Linear, GitHub Issues** are critical for this persona
- **Cross-project Today view** is the core value — she can't use it if it only works with native items
- **Time tracking integration** (native or Toggl MCP) would eliminate her last separate tool
- **Multi-org support** (future) directly addresses her need for client isolation
- **Financial module** (future) would make this her single operational surface
- **Agent as "chief of staff"** — she needs the planner agent to understand client boundaries and billing
