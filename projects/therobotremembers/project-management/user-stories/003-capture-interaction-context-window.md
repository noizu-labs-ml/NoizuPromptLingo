# Capture surrounding interaction context at memory formation

**As** The Archivist,
**I want to** store a context window of surrounding interactions (preceding and following turns) alongside each memory,
**So that** recall can reconstruct the conversational flow that produced a memory, not just the memory in isolation.

## Acceptance Criteria
- [ ] Each memory stores references to the N preceding and M following interaction turns (configurable, default N=3, M=2)
- [ ] Context window entries are stored as lightweight references (turn IDs + summaries), not full transcripts
- [ ] The context window captures who was speaking (agent, user, system) per turn
- [ ] Context windows are back-filled asynchronously — the memory is stored immediately, context window populated within 5 seconds
- [ ] If the memory is the first or last in a session, the window is truncated gracefully with boundary markers

## Scenario: Mid-conversation memory with full context available
- **Given** a 20-turn conversation where a key insight occurs at turn 12
- **When** The Archivist forms a memory from turn 12
- **Then** the context window includes summaries of turns 9-11 (preceding) and turns 13-14 (following), each with speaker labels and timestamps

## Scenario: Memory at session start
- **Given** a memory formed from the second turn of a new session
- **When** The Archivist captures the context window
- **Then** the preceding context contains only turn 1 with a `session_start` boundary marker, and the following context is populated normally

## Technical Notes
- Context windows are critical for The Weaver's association building — isolated memories are harder to link
- Store summaries, not raw text, to manage storage costs; summaries should be generated by a lightweight summarizer
- Consider a separate context_window collection/table to avoid bloating the primary memory record
- Back-fill mechanism needs a short-lived queue or event to capture following turns
