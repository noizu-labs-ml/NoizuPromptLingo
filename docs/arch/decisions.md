# Architectural Decision Records

## ADR-001: Next.js App Router over Remix

**Date:** 2026-03-14
**Status:** Accepted

### Context
Choosing between Next.js App Router and Remix for the React frontend framework.

### Decision
Use **Next.js 15 App Router**.

### Rationale
- **Vercel deployment**: Target users (solo devs, indie hackers) are familiar with Vercel
- **Server Components**: Reduced client-side JavaScript for better initial load
- **Streaming support**: Important for streaming agent output during Ink phase
- **Built-in optimizations**: Image, font, metadata handling out of the box
- **Larger ecosystem**: More examples, tutorials, and third-party integrations

### Consequences
- **Pros**: Faster initial page loads, built-in image optimization, Vercel alignment
- **Cons**: Smaller community than Next.js Pages Router at time of initial research

## ADR-002: Theme-Specific CSS Files over CSS-in-JS

**Date:** 2026-03-14
**Status:** Accepted

### Context
Choosing styling strategy: CSS Modules, Tailwind, styled-components, or theme-specific CSS files.

### Decision
Use **theme-specific CSS modules** with CSS custom properties.

### Rationale
- **Team collaboration**: Designers familiar with CSS can work alongside developers
- **Runtime performance**: No JavaScript parsing at runtime for styles
- **Theme isolation**: Each theme's styles in separate file prevents conflicts
- **Debugging**: DevTools shows actual CSS, not generated class names
- **No runtime JS**: Critical for keeping client bundle small during early phases

### Consequences
- **Pros**: Faster runtime, designer-friendly, easier to export as standalone HTML
- **Cons**: Manual maintenance of theme consistency, less tooling assistance

## ADR-003: 5 Fixed Themes over Dynamic Generation

**Date:** 2026-03-14
**Status:** Accepted (for v0.1)

### Context
Should themes be pre-defined or dynamically generated by AI during Draft phase?

### Decision
Start with **5 pre-defined themes**. Plan dynamic generation for later versions.

### Rationale
- **Proof of concept**: Demonstrates style guide generation capability without AI dependency
- **Performance**: No LLM calls needed for theme exploration in early builds
- **Quality control**: Curated themes ensure consistent, polished visual output
- **Scope management**: Allows focus on pipeline implementation before introducing AI styling

### Consequences
- **Pros**: Faster iteration, predictable output, lower costs
- **Cons**: Limited variety, users constrained to 5 aesthetics
- **Future**: Dynamic theme generation planned for Draft phase AI integration

## ADR-004: Component API over Conditional Rendering

**Date:** 2026-03-14
**Status:** Accepted

### Context
How to implement theme switching: conditional rendering inside components or separate theme files?

### Decision
Use **separate theme files** with a unified component API.

### Rationale
- **Separation of concerns**: Theme code isolated from component logic
- **Maintainability**: Adding/modifying themes doesn't affect existing components
- **Performance**: No runtime conditionals in hot code paths
- **Type safety**: TypeScript ensures all themes export same interfaces

### Consequences
- **Pros**: Faster builds, easier to add new themes, clearer code organization
- **Cons**: More files to maintain (70 theme files for 5 themes)

## ADR-005: Standalone HTML Style Guides

**Date:** 2026-03-14
**Status:** Accepted

### Context
Should style guides only exist in the app or also as standalone HTML files?

### Decision
Export **standalone HTML files** alongside the React app.

### Rationale
- **Early delivery**: Style guides can be shared and reviewed before full app exists
- **No dependencies**: HTML files work without build step or hosting
- **Marketing asset**: Style guides serve as portfolio work and promotional material
- **Export capability**: Validates the "export" deliverable described in product spec

### Consequences
- **Pros**: Shareable immediately, no build required, good for portfolio
- **Cons**: Two code paths to maintain, potential divergence with app version
