# US-091: LLM Snippet Version History

As a developer,
I want every edit to a snippet's system prompt to create a new version,
so that I can compare prompt iterations and track which versions perform better.

## Scenario: Automatic versioning on prompt edit
Given a snippet exists with version 1
When the user edits the system_prompt and saves
Then a new version (version 2) should be created
And the previous version should be preserved in the version history

## Scenario: Manual version bump
Given the user wants to create a new version without changes
When the user selects "Create New Version"
Then a copy of the current version should be created with incremented version number
And the user can then make changes to the new version

## Scenario: View version history
Given a snippet has multiple versions
When the user views snippet details
Then a version history list should display all versions with: version number, timestamp, model, avg_score, sample_count

## Scenario: Compare versions
Given a snippet has multiple versions
When the user selects two versions to compare
Then a side-by-side diff of their system prompts should be displayed
And differences should be highlighted

## Scenario: Set current version
Given a snippet has multiple versions
When the user selects a non-current version and chooses "Make Current"
Then that version becomes the default for new invocations
And previous invocations remain linked to their versions

## Scenario: Delete old version
Given a snippet has multiple versions
When a version is deleted
Then the version should be removed from the history
But invocations that used that version should preserve their version reference

## Notes
- **Persona**: developer
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Storage growth with many versions, maintaining references
- **Dependencies**: US-087 (Create LLM Snippet), US-090 (Rate LLM Snippet Output)
