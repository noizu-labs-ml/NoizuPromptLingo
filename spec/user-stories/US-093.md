# US-093: LLM Snippet Eval Framework

As a developer,
I want to run evaluations across snippet versions to compare performance,
so that I can objectively determine which system prompt produces better results.

## Scenario: Eval framework overview
Given the user wants to evaluate snippet performance
When viewing snippet details
Then an "Eval" section should be available with evaluation options

## Scenario: Manual scoring evaluation
Given a snippet has historical invocations
When the user selects "Manual Scoring Evaluation"
Then an aggregation of all manual scores should be displayed per version
And the version with highest average score should be highlighted

## Scenario: A/B Testing two versions
Given a snippet has at least two versions
When the user selects "A/B Test" and chooses two versions
Then both versions should be run against a set of test inputs
And side-by-side results should be displayed for comparison

## Scenario: Batch re-evaluation
Given a snippet has new versions with changed prompts
When the user selects "Batch Re-eval"
Then historical inputs can be run through the new version
And new outputs should be generated for comparison with original results

## Scenario: Auto-evaluation with judge LLM
Given LLM API is configured
When the user selects "Auto-eval"
Then a "judge" LLM should evaluate outputs against criteria (accuracy, completeness, tone)
And scores should be stored alongside user ratings

## Scenario: Evaluation dashboard
Given an evaluation is complete
When the user views the Eval Dashboard
Then aggregate metrics should display: avg_score per version, sample counts, confidence intervals
And charts should show score trends over time

## Notes
- **Persona**: developer
- **T-Shirt Size**: XL
- **Complexity**: very-high
- **Risks**: LLM API costs, evaluation bias, statistical significance
- **Dependencies**: US-091 (LLM Snippet Version History), US-092 (LLM Snippet Invocation History)
