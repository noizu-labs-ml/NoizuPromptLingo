# US-029: Background daemon startup reliability

As a knowledge-worker,
I want the clipboard daemon to reliably start in the background,
so that clipboard history is always available without requiring manual intervention.

## Scenario: Daemon starts on app launch
Given I launch Smart Clipboard
When the application initialization completes
Then the background clipboard monitoring daemon should be running and monitoring clipboard changes

## Scenario: Daemon starts via launch agent (auto-start)
Given auto-start is enabled
When I log into macOS
Then the clipboard monitoring daemon should be running within 5 seconds of desktop appearance

## Scenario: Verify daemon health
Given Smart Clipboard is running
When I query the daemon status
Then the status should show "Running" with a heartbeat response within 500ms

## Scenario: Restart crashed daemon
Given the clipboard monitoring daemon has unexpectedly crashed
When the main app detects the crash
Then the daemon should be automatically restarted within 2 seconds

## Scenario: Report daemon failure to user
Given the daemon fails to start after 3 automatic restart attempts
When the main app detects this condition
Then a user-facing alert should appear indicating that clipboard monitoring has failed

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Daemon persistence can be fragile on macOS; sandboxing may interfere
- **Dependencies**: US-020
