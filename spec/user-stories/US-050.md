# US-050: Recovery from empty or corrupted database

As a knowledge-worker,
I want the application to recover gracefully from database corruption,
so that I can continue using it without losing recent data or reinstalling.

## Scenario: Detect corrupted database
Given the database file contains corrupt or invalid data
When the application attempts to open the database
Then the app should detect the corruption and display a user-friendly error message

## Scenario: Recovery with backup database
Given the main database is corrupted but a recent backup exists
When the application detects corruption
Then the app should automatically restore from the most recent backup with minimal data loss

## Scenario: Recovery without backup (empty start)
Given the database is corrupted and no backup is available
When the application starts
Then the app should create a new, empty database, inform the user of the situation, and offer to try a data repair

## Scenario: Attempt data repair from corrupted database
Given the database is corrupted
When I select "Attempt Repair" from the recovery options
Then the app should attempt to salvage clipboard items marked as valid and rebuild a new database

## Scenario: Report recovery outcome to user
Given a database recovery operation completes
When the operation finishes
Then the app should display a summary showing how many items were recovered (or that a new database was created)

## Scenario: Preserve older backup after recovery
Given a backup database was used for recovery
When the recovery completes successfully
Then the old corrupted database and the backup should be preserved as files with ".corrupted" extension for potential manual recovery

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Data loss is unacceptable; backup strategy must be reliable; corruption detection must be robust
- **Dependencies**: None
