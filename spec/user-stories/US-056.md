# US-056: CLI interface for clipboard operations

As a developer,
I want a command-line interface for clipboard operations,
so that I can automate clipboard management and integrate it with other workflows.

## Scenario: List clipboard items via CLI
Given the CLI is installed
When I run `smart-clipboard list --limit 10`
Then the most recent 10 clipboard items should be displayed with metadata (ID, timestamp, preview)

## Scenario: Get specific clipboard item via CLI
Given the CLI is installed and I know a clipboard item ID
When I run `smart-clipboard get <ID>`
Then the clipboard item content should be output to stdout (or saved to file with `--output` flag)

## Scenario: Copy item to system clipboard via CLI
Given the CLI is installed
When I run `smart-clipboard copy <ID>`
Then the specified clipboard item should be copied to the system clipboard

## Scenario: Search clipboard history via CLI
Given the CLI is installed
When I run `smart-clipboard search "search term"`
Then matching clipboard items should be displayed with their IDs and timestamps

## Scenario: Delete clipboard item via CLI
Given the CLI is installed and I know a clipboard item ID
When I run `smart-clipboard delete <ID>`
Then the specified clipboard item should be removed from history

## Scenario: Export clipboard history via CLI
Given the CLI is installed
When I run `smart-clipboard export --output history.json`
Then the clipboard history should be exported to a JSON file at the specified path

## Scenario: Clear all clipboard history via CLI
Given the CLI is installed
When I run `smart-clipboard clear --force`
Then all clipboard history should be removed (requires `--force` flag to prevent accidental data loss)

## Scenario: Get app status via CLI
Given the CLI is installed
When I run `smart-clipboard status`
Then information about app status, daemon health, and sync status should be displayed

## Notes
- **Persona**: developer
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: CLI must use same database access libraries; need proper error handling and security for credentials
- **Dependencies**: None
