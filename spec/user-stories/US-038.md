# US-038: Encrypted local storage

As a knowledge-worker,
I want the local clipboard history database to be encrypted,
so that my clipboard data is protected if my device is lost or compromised.

## Scenario: Enable local encryption
Given local storage encryption is not enabled
When I enable "Encrypt local storage" in the Security settings
Then a new encryption key should be generated, stored in the macOS Keychain, and the database should be re-encrypted

## Scenario: Database encrypted at rest
Given the application is not running
When an attacker accesses the device and opens the database file directly
Then the clipboard data should be encrypted and not readable without the encryption key

## Scenario: Decrypt database on startup
Given the database is encrypted locally
When the application starts
Then the database should be automatically decrypted using the Keychain-stored key for normal operation, with no user-visible delay

## Scenario: Handle missing encryption key
Given the database is encrypted locally
When the application starts and the encryption key is not available (deleted from Keychain)
Then the app should prompt the user to recover or recreate the key, and the database should remain inaccessible

## Scenario: Change local encryption key
Given the database is encrypted with an existing key
When I click "Re-encrypt with new key"
Then the database should be decrypted with the old key and re-encrypted with a newly generated key

## Scenario: Disable local encryption
Given the database is encrypted locally
When I disable "Encrypt local storage" with authentication
Then the database should be decrypted and future storage should be in plaintext

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: XL
- **Complexity**: very-high
- **Risks**: Key loss means data loss; performance impact of encryption; key management critical
- **Dependencies**: US-018, US-025
