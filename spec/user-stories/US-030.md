# US-030: Clipboard change monitoring without excessive polling

As a knowledge-worker,
I want clipboard monitoring to be efficient and not consume significant CPU,
so that my battery life and system performance are not impacted.

## Scenario: Initialize clipboard monitoring with observer
Given Smart Clipboard is starting up
When the clipboard monitoring is initialized
Then the system should use NSPasteboard's change notifications (observer pattern) rather than polling at intervals

## Scenario: Clipboard change responds to system notification
Given clipboard monitoring is active
When the system clipboard content changes
Then the monitoring daemon should receive and process the change notification within 10ms

## Scenario: Monitor multiple clipboard types efficiently
Given clipboard monitoring is active
When I copy content with multiple representations (e.g., text + image + RTF)
Then the daemon should capture all types in a single event without triggering multiple callbacks

## Scenario: No monitoring when daemon is idle
Given clipboard monitoring is active
When no clipboard changes occur for 60 seconds
Then the daemon should not be actively polling or consuming CPU cycles

## Scenario: System clipboard type count verification
Given clipboard monitoring is active
When a change notification is received
Then the system should query available pasteboard types only once to determine what content types changed

## Notes
- **Persona**: knowledge-worker
- **T-Shirt Size**: M
- **Complexity**: medium
- **Risks**: Must handle edge cases where NSPasteboard notifications may not fire; need fallback mechanism
- **Dependencies**: US-029
