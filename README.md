# derobot.is — The Robot Venture Lab

**Domain:** [derobot.is](https://derobot.is)

## Elevator Pitch

**The holding company and launch platform for an AI-native product portfolio.** derobot.is is the corporate landing page for a pending Dutch legal entity that incubates, validates, and scales digital products under the "therobot" brand family — therobotlives, therobotknows, therobottutors, and more. Each product lives at its own domain, gets tested with targeted marketing, and either earns continued investment or gets shelved — fast.

The tagline: **"The robots build. The robots share."**

---

## Problem

### Building Products Is Easy. Knowing Which Ones Deserve Investment Is Hard.

The bottleneck for solo founders and small studios isn't ideas — it's validation. The typical failure mode:

1. **Spend months building** a product based on gut feel
2. **Launch to silence** because no market was validated first
3. **Pivot too late** because sunk cost makes you irrational
4. **Repeat** with the next idea, same pattern

What's missing is a **structured pipeline** that treats product ideas like experiments: hypothesis → minimum viable page → targeted traffic → read the data → build or kill. The venture lab model does this at the organizational level — not one product at a time, but a portfolio of bets running in parallel, sharing infrastructure, brand equity, and operational knowledge.

### The Credibility Gap

A portfolio of ideas living on separate domains with no visible parent looks scattered. Investors, partners, and customers can't see the system behind the products. There's no "this is from the same team that built X" halo effect. Each product starts cold.

derobot.is solves this by being the visible roof — the entity that gives every product inherited credibility and a shared story.

## Brand Architecture

### The therobot Naming Pattern

"therobot" is the brand family convention — a naming pattern that connects products through a shared linguistic thread. The robot builds. The robot lives. The robot tutors. The robot knows. Each product inherits the pattern while owning its own identity.

```
therobot{verb}s                     ← Naming pattern (not a social handle)
  │
  ├── derobot.is                    ← Corporate entity + landing page
  │
  ├── therobot{verb}s.com           ← Product domains
  │   ├── therobotlives.com         ← Agentic social network
  │   ├── therobottutors.com        ← AI-assisted study app
  │   ├── therobotknows.com         ← Knowledge/search product
  │   ├── therobotmakes.com         ← Guided pipeline from idea to running product
  │   └── therobotstates.com        ← Data/analytics product
  │
  ├── {verb}.derobot.is             ← Subdomain products (lightweight / incubating)
  │   └── (none currently — products have graduated to standalone domains)
  │
  └── {standalone}.com              ← Products with their own brand identity
      ├── bladeofeternity.com       ← Accessibility-first text RPG
      ├── codefre.sh                ← Agent evaluation framework
      ├── gotta.cc                  ← AI-curated web directory
      ├── aifighter.com             ← Neural-net fighting game
      ├── iotgo.io                  ← IoT fleet management
      └── (etc.)
```

### Naming Tiers

- **therobot{verb}s.com** — Products that fit the naming pattern. The convention creates brand family recognition across domains.
- **{verb}.derobot.is subdomains** — Lightweight products incubating under the parent domain. Dutch verbs signal function. Cheap to stand up, clearly part of the parent.
- **Standalone domains** — Products with their own identity. No naming constraint. These may or may not reference the parent brand.

### Brand Voice

| Attribute | Expression |
|---|---|
| **Tone** | Direct, competent, slightly irreverent. Not corporate. Not cute. |
| **Perspective** | First-person plural ("we build") when representing derobot.is. Third-person ("the robot knows") when naming products. |
| **Personality** | The robot is a character — not a mascot, not a logo. It's the thread connecting every product. It builds. It teaches. It knows. It lives. |
| **Language** | Dutch roots (domain, subdomain verbs) with English-first content. The Dutch elements add distinctiveness, not barriers. |

### Design Independence

Each product owns its own visual identity. derobot.is provides brand voice guidelines and the naming convention — not a shared design system, component kit, or token set. Products are free to choose their own styles, palettes, and typography to match their audience and market.

### Portfolio Grid Design

All products are currently at Concept stage. The grid's job isn't to show progress — it's to show **breadth, intentionality, and range**. The grid should:

- **Group by category** — AI/Dev Tools, Gaming, Knowledge, Social, Security, IoT — so the portfolio reads as a deliberate spread of bets, not a random pile
- **Show each product as a card** — name, domain, one-line pitch, category tag
- **Link to the product** when a landing page or README exists
- **Scale gracefully** from the current 11 active products to more as new ones leave the backburner

No fake status badges. No "coming soon" theater. The cards are honest: these are concepts being developed.

### The Process Section

This replaces the "pipeline visualization with live metrics" from the earlier draft. Since everything is at Concept stage, the pipeline section is **aspirational and methodological** — it explains how the venture lab works, not how far along it is.

```

before building. The data decides what gets investment. Here's the process:"

[Concept] ───→ [Validate] ───→ [Build] ───→ [Scale] ───→ [Spinoff]
 Domain +       Landing page    Full product   Real users   Own legal
```

When products advance past Concept, this section gains real numbers.

## Visual Direction

### Style: Nocturne (80%) + Bold Expressive (20%)

derobot.is is a tech venture lab, not a SaaS product. The audience is builders, investors, and the AI-curious. Nocturne provides the dark, focused, professional foundation. Bold Expressive brings the 20% that says "this isn't another boring startup page" — unexpected typography choices, confident color, and moments of visual surprise.

| Element | Direction |
|---|---|
| **Palette** | True dark background. Monochrome UI chrome. One electric accent color (cyan or green — the "robot" signal). Portfolio cards get product-specific accent colors. |
| **Typography** | Strong display font for the hero and section headers (something with character — not Inter). Clean sans for body. Monospace for data/metrics/status badges. |
| **Layout** | Full-width hero, then bento-grid portfolio section grouped by category. Single-column for narrative sections (The Process, About). Generous whitespace. |
| **Motion** | Subtle — cards have hover states, the process visualization animates on scroll. Nothing gratuitous. Motion communicates state, not personality. |
| **Photography/Imagery** | None. The brand is typographic + the portfolio cards. If illustration is needed, it's geometric/abstract — think data visualization aesthetic. |
| **The robot** | Not a cartoon mascot. If visualized at all, it's abstract — a cursor, a glyph, a geometric form. The personality comes from language, not imagery. |
| **Density** | Low. This is a landing page, not a dashboard. Every element earns its space. |

### Color Palette (Candidate)

```
Background:      #09090B    (near-black, warm)
Surface:         #18181B    (cards, sections)
Text Primary:    #FAFAFA    (headings, key content)
Text Secondary:  #A1A1AA    (body text, descriptions)
Accent:          #22D3EE    (cyan — the robot signal)
Accent Alt:      #A78BFA    (violet — secondary actions, links)
Border:          #27272A    (subtle separation)
```

### Typography (Candidate)

| Role | Font | Reasoning |
|------|------|-----------|
| Display / Hero | Space Grotesk or Syne | Geometric with character — stands out from the Inter/Geist crowd |
| Body | Inter or Geist | Clean, readable, doesn't compete with display |
| Data / Status | JetBrains Mono | Signals precision, used for metrics and category tags |

## Technical Considerations

| Layer | Direction |
|---|---|
| **Framework** | Next.js (App Router) — SSR for SEO, easy to deploy |
| **Hosting** | Vercel — handles subdomain routing for X.derobot.is products |
| **CMS / Data** | Markdown-driven (portfolio data lives in this repo). Each project's README is the source of truth. |
| **Portfolio cards** | Generated at build time from `portfolio-projects/` (excluding `backburner/`). Each README provides the card data. |
| **Subdomain routing** | Vercel rewrites or DNS-level routing. Each subdomain product is its own app or a route within derobot.is. |
| **Analytics** | Plausible or Fathom (privacy-respecting). Track: portfolio card clicks, contact form submissions, time on process section. |
| **Legal** | Minimal until BV is registered. "Based in the Netherlands" + pending entity status. |

### Build-Time Portfolio Generation

The landing page pulls project data from the repo:

```
portfolio-projects/
  ├── {active-project}/
  │   └── README.md   →  parse sections  →  portfolio card data
  │                       (name, domain, category, one-liner)
  └── backburner/
      └── (excluded from build)
```

New active project = new directory at root level = new card on the site. No manual content management.

## Monetization Angle

derobot.is itself doesn't monetize — it's the cost center that enables everything else. Its value is:

| Function | Value |
|---|---|
| **Brand credibility** | Products inherit trust from a visible parent entity |
| **Pipeline visibility** | Investors/partners can see the portfolio and velocity |
| **Talent attraction** | Collaborators can see what's being built and where to plug in |
| **Legal structure** | Dutch entity (when registered) provides the entity for contracts, IP, banking |
| **Shared infrastructure** | DNS, hosting, analytics shared across products |

Revenue comes from the portfolio products. derobot.is is the operating system, not the product.
